# Beta Preview AI 정책 종합 검증

## 범위와 확인 수준

대상은 `feat/glass-nebula-aurora`의 Beta Preview다. 운영 DB 연결 대상은 미확인 상태이며 계정·비용 기록을 조회하거나 수정하지 않는다. 실제 OpenAI 요청도 하지 않는다. 인증 진단 미커밋 작업, ZIP, 환경 파일, 오로라 디자인과 의미 계산은 별도 작업으로 보존한다.

기존 `AI_BUDGET_LIMIT`는 사용자 월·전역 일·전역 월 중 하나 이상에서 **기존 장부의 charged_usd 합계 + 이번 요청의 최악 예약액 > 유효 한도**일 때 발생한다. 과거 배포에는 세 조건을 구분하는 로그가 없었으므로 이번 실제 오류의 세부 원인은 소급 확정할 수 없다. Secret 및 실제 DB 값을 추측하지 않는다.

## Preview 전용 진단

`[private-beta-usage-limit]`는 실패할 때만 다음 allowlist 필드를 기록한다.

- 고정 stage/code/feature와 모든 해당 reasons. `USER_MONTH_USD`, `GLOBAL_DAY_USD`, `GLOBAL_MONTH_USD`를 동시에 판별한다.
- `userBudgetSource: account | environment`, 유효 한도·이미 장부에 반영된 금액·이번 예약액.
- 해당 기능의 개인 일간 사용량/한도, 전역 횟수/동시 실행 수/한도, 입력·출력·시도 상한.

따라서 다음 거부 로그에서 낮은 계정 override, 이미 소진된 예산, 예상과 다른 예약액을 구분할 수 있다. 응답에는 잔액·계정 설정을 노출하지 않는다. `[private-beta-usage-accounting]`는 SDK가 보고한 안전한 토큰 숫자와 모델별 추정액, 최종 예약액·장부 반영액을 구분한다. 정산 로그는 DB 트랜잭션이 성공한 뒤 기록한다. 이 숫자는 공급자 청구서가 아니다.

두 로그 모두 `VERCEL_ENV=preview`에서만 동작한다. 원본 답변, 승인 문장, 프롬프트, 모델 응답, ID·digest·이메일·비밀번호·키·쿠키·토큰·DB URL·전체 환경 JSON·스택은 기록하지 않는다. logger에 임의 필드를 전달해도 재구성한 allowlist만 출력한다. 로그 실패는 원래 차단·시도·정산을 바꾸지 않는다. 공개 디버그 API는 없다.

## 비용과 예상 차단 지점

확인일: 2026-10-18 KST. 공개 표준 텍스트 단가는 백만 토큰당 다음과 같다: GPT-4o mini 입력 $0.15 / 캐시 입력 $0.075 / 출력 $0.60, GPT-6.1 Sol 입력 $2 / 캐시 입력 $0.10 / 출력 $10. [GPT-4o mini 공식 문서](https://developers.openai.com/api/docs/models/gpt-4o-mini), [GPT-6.1 Sol 공식 문서](https://developers.openai.com/api/docs/models/gpt-6.1-sol).

운영 Secret 가격표를 읽거나 변경하지 않았으므로 아래는 **공개 단가와 같은 가격표라는 가정하의 계산**이다. 실제 운영 예약액은 기존 Secret의 단가를 사용한다. 실제 모델 사용량이 확인되지 않은 요청을 평균 비용으로 단정하지 않는다.

현재 Preview의 기존 안전한 모델 로그를 제한된 최근 조회 범위에서 확인했지만 토큰 기록은 0건이었다. 따라서 이번 사용자 요청의 실제 토큰 수·청구액은 미확인이다. 신규 회계 로그는 이후 정상 요청의 보고 토큰과 추정액을 DB 직접 조회 없이 구분하기 위한 것이다.

| 요청 | 최대 입력·출력 기준 1시도 | 전체 요청의 최대 예약 | 사용량 확인 시 예시 (실사용이 아닌 테스트 값) |
|---|---:|---:|---:|
| Q10 | $0.018108 | $0.018108 (1회) | 입력 2,000 + 출력 100, 캐시 없음 → $0.00036 |
| 오로라 | $0.49 | $0.98 (최대 2회) | 입력 8,000 중 캐시 1,000 + 출력 4,000 → $0.0541 / 2회 동일 사용량이면 $0.1082 |
| Q10 + 오로라 전체 흐름 | — | $0.998108 | 실제 청구 추정은 각 시도의 유효 사용량 비용 합계 |

계산식은 `((입력-캐시)*입력단가 + 캐시*캐시단가 + 출력*출력단가) / 1e6`이며 예약은 캐시 할인을 가정하지 않고 `입력상한+출력상한`의 비용 × 최대 시도를 소수 8자리 올림한다. 실제 사용량 확인 후 각 시도도 소수 8자리 올림해 장부에 합산한다.

- 정상 응답·유효 사용량: 전체 예약 대신 확인된 시도 비용만 반영한다.
- 모델 호출 전 거부: 새 모델 호출·비용 없음. 생성된 예약이 있으면 no-model 0 정산.
- 모델 호출 후 시간 초과·취소·네트워크 실패·누락/상한 초과 사용량: 불확실한 비용을 0으로 만들지 않고 **요청 전체 예약**을 유지한다. 첫 해석 시도만 실패해도 $0.98을 유지할 수 있다. 이는 실제 $0.98이 청구됐다는 뜻이 아니다.
- SDK가 늦게 응답하더라도 임의로 환불하거나 새로운 시도를 시작하지 않는다. DB 장애 시 정산 실패는 pending 예약 또는 만료 후 보수적 금액으로 남을 수 있다.
- 빈 장부이고 매번 최악 금액이 남는다면 Q10+해석 50회는 약 $49.9054다. 다만 100회/일 전역 요청 한도는 보통 흐름 50회에 도달하고, 개인의 Tester 3회/Owner 10회 해석 한도는 그보다 먼저 적용된다. 기존 장부가 있거나 Q10 재생성이 반복되면 여유는 더 적다.

## UX·재시도

429를 모두 단순 대기 오류로 바꾸던 클라이언트 매핑만 수정했다. 카드·리본·분석 UI는 수정하지 않는다.

- 금액 부족: `AI_BUDGET_LIMIT`를 유지하고 관리자/기간 예산 확인을 안내한다. 보장할 수 없는 `Retry-After: 60`을 제거한다. 예약 자체가 계정 한도보다 크면 월이 바뀌어도 해결되지 않으므로 임의 시각을 제시하지 않는다.
- 개인 일간: DB 시계 기준 다음 한국 시간 자정까지의 정확한 Retry-After.
- 전역 일/월 횟수: 해당 소진 기간의 다음 한국 경계. 둘 다 소진되면 월 경계를 사용한다.
- 중복: 기존 요청 시작에서 60초까지 남은 초. 진행 중 요청은 먼저 완료를 기다린다.
- 분당 빈도: 기존 60초 대기. 서버 장애·세션 만료·시간 초과는 각각 기존 별도 오류 계약을 유지한다.
- 자동 유료 재시도는 추가하지 않는다. 오로라 실패는 질문 상태·Q10 승인을 그대로 보존한다. Q10 재생성 시작 시 기존 승인 무효화 정책은 유지하며, 실패를 이유로 과거 승인을 자동 복원하지 않는다.

## 검증과 후속 조치

단위 테스트는 세 USD 조건·복합 소진·계정 override 우선순위·새 예산 아래 전체 라우트/클라이언트 흐름·정산·모델 재시도·일간/월간/중복/동시 제한·로그 안전성을 검사한다. 기존 시간 초과 테스트는 WebCrypto 준비 완료를 기다리는 검사 장벽만 보완했다. 70/85/95초 상수와 실제 계산은 변경하지 않는다.

독립 임시 PostgreSQL에서 기존 로그인·권한·출처·예산 원자성 테스트와 승인 설정의 Q10→해석 예약/실사용 정산, 계정 override 차단, 사용자 20/전역 100 분당 한도를 검증한다. 운영 DB가 아닌 임시 DB만 쓰고 컨테이너는 삭제한다.

Preview 회계 로그 추가 후 병렬 예약 테스트의 워커 stdout에 로그가 섞이는 문제가 확인돼, 해당 테스트 도구의 stdout은 단일 JSON 결과로 유지하고 진단은 stderr로 분리했다. 제품의 비용·동시 실행 규칙을 완화한 조치는 아니다.

Preview 적용은 다섯 승인 설정 $50/$50/$200 및 100/1,000만 갱신한다. 모두 Preview 전용 Secret인지 먼저 확인하고 공용·Production 범위가 있으면 중단한다. 기존 가격표·동시 실행·두 입력 상한·나머지 Secret을 보존하며 커밋만 추출한 소스를 배포해 READY·프로젝트·커밋·고정 alias를 확인한다.

운영 DB의 실제 monthlyBudget·개인 일간 값·기존 누적액·전역 동시 실행 값은 아직 미확인이다. 낮은 계정 override나 개인 일간 소진은 환경 $50만으로 해결하지 못한다. 새 진단으로 원인이 확인되면 **실제 DB 대상을 확인하고 별도 승인된 계정 한도 변경**이 필요하다. 비용 기록 초기화·계정 override 우회·무조건적인 생성 성공은 제공하지 않는다.
