## 중심장·미스트 보정 — 이전 작업 기록

이번 변경은 `/aurora-lab` 렌더러와 오로라 데이터/검사에 한정합니다. 실험 패널의 구조·옵션·기본 모드, 질문·캡슐 물리·하늘·Q10·승인·기존 분석/OpenAI API·결과 화면, 별·유리 조각·성운 레이어를 보존했습니다.

### 핵심 변경

- 공통 중심을 `AURORA_ORBITAL_ANCHOR = [0, 0.15, -0.6]`에 둡니다. 공통 그룹의 큰 이동을 줄여 제한된 중심 주변에서 호흡하도록 했습니다. 개별 리본의 XY 배치를 중앙으로 모으고 공전 반경을 줄였습니다. 각 리본의 Z 차이는 유지하며, 전체가 같은 중심 안에서 서로 다른 위상·곡률을 갖습니다. 외부 진폭/강도가 높아도 중심 이동이 지나치게 커지지 않도록 공간 운동에 상한을 둡니다.
- 독립 리본 공전 계수는 0.72에서 0.42, 연결 루프는 0.26으로 낮췄습니다. 공통 위상 계수도 0.6에서 0.32로 낮춥니다. 루프의 누적 X/Z 자전을 제거하고 제한된 범위의 느린 다축 기울기 변화로 바꿨습니다. 지오메트리의 반 꼬임 연결은 유지하고 깊이 굽힘을 강화합니다.
- 루프에 넓이가 약 1.75/2.05배이고 깊이가 조금 다른 반투명 미스트 곡면을 겹칩니다. 같은 중심·위상·팔레트·공전 및 연결부 규칙을 공유하며 코어 바깥으로 퍼지는 부드러운 감쇠와 길이 방향으로 이동하는 절차적 미스트를 사용합니다. 이는 여러 얇은 곡면으로 볼륨감을 근사한 것으로, 실제 볼륨 광산란이나 ray marching은 아닙니다.
- 루프 본체 알파 비율을 독립 리본의 72%에서 58%로, 유색 코어 계수를 2.05에서 1.25로 줄입니다. 루프의 에너지·필라멘트 대비·가장자리 광도도 낮추고 노이즈가 낮은 구간을 더 희미하게 만듭니다. 전체 고리 실루엣을 균일하게 밝히지 않고 일부가 안개로 녹아들도록 했습니다. 미스트는 코어 없는 약한 유색 층이며, 본체 기본 알파의 34%를 사용합니다.
- 독립 리본의 색/코어/노이즈와 Bloom 0.32 설정은 유지했습니다. 모든 추가층도 기존 청록·라벤더·분홍 계열 팔레트와 Normal blending을 사용하며 순백색 하이라이트를 추가하지 않습니다.
- 시스템/수동 움직임 감소에서 코어와 미스트 모두 동일하게 정지합니다. 누적 위상, 모드 알파 전환, 프리셋 보간, 숨김 정책, 자원 정리는 유지합니다. 프레임 루프에서 새 객체/정점 배열이나 React 상태를 만들지 않습니다.

### 실제 화면의 남은 확인

브라우저에서는 「독립 고리가 회전하는 인상」이 줄었는지, 루프 일부가 안개에 녹아드는지, 전체 에너지가 중심에 모이는지, 유색 코어와 흰색 겹침이 적절한지 확인해야 합니다. 세 모드·네 프리셋·모바일 품질과 움직임 감소도 비교해야 합니다. 미스트는 추가 투명 draw/overdraw 비용이 있고, 중심 깊이 정렬만으로 자기 교차 면을 완벽히 정렬하지는 못합니다. 반복 전환 후 GPU 메모리와 자원 해제도 실제 측정이 필요합니다. 자동 데이터 검사가 실제 미학·셰이더 실행·FPS·메모리 누수 부재를 검증한 것은 아닙니다.

## Hybrid Orbital Aurora — 이전 개정판 기록

이번 변경은 `/aurora-lab`에 한정합니다. 기존 질문·캡슐 물리·하늘·Q10·승인·분석/OpenAI API·실제 결과 화면과 의미 팔레트/프리셋은 변경하지 않았습니다.

### 구성과 연결부

- 기본은 `Hybrid Flow`이며 독립 리본 2~4개(기존 선택값)와 연결 루프 1개를 표시합니다. `Independent`는 루프 0개, `Loop Emphasis`는 루프 2개입니다. 독립 리본 수는 모드 변경과 무관하게 유지합니다. 기존 움직임 강도 선택도 유지합니다.
- 두 루프 프로필은 서로 다른 반경·폭·깊이·기울기·위상·공전 방향을 갖습니다. 장축 약 4.1/3.4, 단축 약 1.75/1.45인 타원 중심선에 2·3차 저주파 변화와 깊이 굽힘을 넣었습니다. 단면은 한 바퀴에 반 바퀴 꼬여 `u=0,v`와 `u=1,1-v`가 연결됩니다. 튜브나 금속 재질을 추가하지 않고 기존 얇은 리본 곡면과 ShaderMaterial을 재사용합니다.
- UV를 위해 연결부 정점은 중복하지만 실제 위치는 역순 폭 정점과 일치시킵니다. 연결 루프의 정점 변형은 주기적이며, 표면 노이즈에는 원형 좌표와 대칭 폭 좌표를 사용합니다. 끝 알파 마스크도 루프에서는 끄고 폭 가장자리만 부드럽게 감쇠시켜 연결부의 틈을 막습니다. 최종 GPU에서의 부동소수점·드라이버 동작은 미검증입니다.

### 세 계층 운동

- 공통 장 43%: 모든 독립 리본과 루프를 하나의 그룹에 두고, 보이지 않는 중심의 타원형 XYZ 이동과 여러 축의 완만한 회전을 공유합니다. 별·성운·유리·카메라는 기존 구조를 유지합니다.

## 리본의 실제 3D 구성

- 각 리본은 `u / v` 방향의 격자를 실제 XYZ 곡면에 배치한 인덱스 BufferGeometry입니다. 전체 삼각형으로 연결된 넓고 얇은 2차원 면이며, 3차원 공간에서 비평면인 커튼을 만듭니다.
- 곡면의 폭·높이·굽힘·깊이가 별도 파라미터이며 높이도 진행 방향에 따라 변합니다. 리본은 Z=1.9, -0.4, -3.1, -5.2의 다른 위치와 서로 다른 회전으로 배치됩니다. 조작 패널에서 2~4개를 선택합니다.
- 리본 전체의 기울어진 타원 공전과 회전 위에 서로 다른 주파수·위상·진폭·부호가 있는 정점 파동, 역방향 보조 파동, 공통 위상의 큰 파동과 단면 비틀림을 사용합니다. UV 접선과 변형된 이웃 위치로 법선을 근사해, 접히는 면의 시선 변화가 Fresnel에 반영되게 했습니다.
- 끝과 상하 경계는 알파 마스크로 부드럽게 사라집니다. 희미한 다수의 필라멘트, 색상 혼합과 얇은 내부 발광을 사용합니다. 기존 `MeshDistortMaterial`이나 구체·튜브·선은 사용하지 않습니다.
- Normal blending, DoubleSide, depthWrite=false, forceSinglePass와 중심 깊이 기반 투명 정렬을 적용했습니다. 각 면 안에서 접힌 삼각형이나 교차 리본의 모든 투명도 순서를 완벽히 해결하는 OIT는 구현하지 않았습니다. 실제 겹침 품질은 브라우저 확인 항목입니다.

## 공간 레이어와 광학 효과

- 배경색은 `#080d23`입니다. 카메라 뒤쪽 공간에는 -19부터 -55까지 다른 깊이의 넓은 성운 면을 놓고, 4옥타브 fBm·도메인 변형·느린 드리프트를 셰이더로 계산합니다. 텍스처나 원격 이미지 다운로드를 사용하지 않습니다.
- 먼 별은 Z=-28~-83, 가까운 먼지는 Z=-8~7에 고정 예산으로 생성합니다. 크기는 원근과 DPR에 따라 달라지며 soft point sprite·완만한 밝기 변화·느린 GPU 부유·오로라 flow에 따른 반응을 적용합니다. 프레임마다 입자를 생성하거나 CPU 위치 배열을 다시 쓰지 않습니다.
- 전경에는 8~18개의 작은 팔면체 프리즘을 하나의 InstancedMesh로 배치합니다. 면 법선, Fresnel, 반사 방향의 작은 하이라이트와 투명도로 유리를 근사합니다. 화면 전체의 물리 굴절·환경맵·전송 재질은 사용하지 않습니다.
- 후처리는 `RenderPass → BloomEffect → ToneMappingEffect(ACES_FILMIC)` 순서입니다. 장면 렌더러에는 중복 톤 매핑을 적용하지 않습니다. 반투명 리본의 좁은 내부와 유리 하이라이트를 HDR로 밝히고, 성운은 어둡게 유지합니다.
- Bloom 강도는 0.32이며 HDR 경로의 휘도 문턱은 1.12입니다. 저사양 또는 `EXT_color_buffer_float` 미지원이면 8비트 타깃과 문턱 0.84를 사용합니다. 휘도 smoothing은 0.3이며 Bloom 높이는 품질·화면 예산으로 제한하고 폭은 종횡비에 맞춥니다. 셰이더의 유색 발광을 중심으로 읽히게 하고 후처리 번짐은 선택적으로 줄였습니다.
- 배경·리본·전경은 서로 다른 실제 위치에 있으므로 제한된 카메라 드래그와 약한 포인터 시차가 각 깊이에 다르게 반영됩니다. 자동 회전·갑작스러운 줌·팬은 사용하지 않습니다.

## 외부 입력 인터페이스

`GlassNebulaAuroraProps`:

```ts
{
  appearance: {
    palette: readonly { familyId: SemanticFamilyId; weight: number; color?: string }[];
    motion: { speed: number; amplitude: number; flow: number; intensity?: number };
    ribbonCount: 2 | 3 | 4;
  };
  quality?: "low" | "balanced" | "high";
  layers?: { nebula: boolean; ribbons: boolean; glass: boolean; stardust: boolean; bloom: boolean };
  reducedMotion?: boolean;
  flowMode?: "independent" | "hybrid" | "loop-emphasis"; // 기본 hybrid
  onPerformanceSample?: (sample: { fps: number; frameMs: number }) => void;
  onAvailabilityChange?: (available: boolean) => void;
}
```

- 기존 일곱 의미 계열의 색을 그대로 가져옵니다. 필요하면 동일 계열에 유효한 HEX 색을 외부에서 지정할 수 있습니다. 색 비율의 합은 1이며 2~7개의 중복 없는 계열을 허용합니다.
- 비율은 리본의 투명도와 색 혼합에 반영됩니다. speed는 접힘과 공전 속도, amplitude는 변형 및 공간 이동 크기, flow는 표면 흐름과 근거리 입자 반응을 조절합니다. 선택적 intensity(0.5~1.5, 기본 1)는 파동·공전·회전의 크기를 조절합니다. 기존 intensity 없는 입력도 유효합니다. preset 데이터나 기존 의미 데이터를 수정하지 않습니다.
- Serenity는 청록·은백색, Connection은 분홍·보라, Exploration은 민트·청록, Mixed는 표현·평온·탐색·추진의 네 계열을 사용합니다. 실제 답변에 대한 성격 판단이나 분석 결과를 생성하지 않습니다.
- 승인 제목은 나중에 소유 화면이 별도의 HTML 영역에 표시하고, 이 컴포넌트에는 시각 파라미터만 전달할 수 있습니다. 현재 실험 화면의 제목은 정적 문구입니다.

## 성능 예산과 최적화

| 품질 | 리본 격자(각 면) | 별+먼지 | 유리 | 성운 면 | DPR 상한 | Bloom 높이 |
|---|---:|---:|---:|---:|---:|---:|
| 저사양 | 56×8 | 600+100 | 8 | 3 | 1 | 192 |
| 기본 | 104×14 | 1300+220 | 12 | 4 | 1.5 | 384 |
| 고화질 | 160×20 | 2200+400 | 18 | 5 | 2 | 640 |

- 작은 화면 및 1100px 이하 터치 기기는 리본 해상도를 약 70%, 입자 수를 60%, 유리 수를 약 70%로 줄이고 성운 면은 최대 3개·DPR은 최대 1.25로 제한합니다. 정확한 정수 예산은 `auroraQualityBudget`에서 관리합니다.
- 고화질의 독립 리본 4개는 총 13,524개 정점, 25,600개 삼각형이며 두 루프 버퍼와 최대 네 미스트 곡면을 합치면 17,646개 정점, 32,704개 삼각형입니다. 입자는 최대 2,600개이며 두 Points로, 유리는 한 InstancedMesh로 그립니다. 그림자·NormalPass·MSAA·물리 굴절·외부 텍스처는 사용하지 않습니다.
- 정점·인덱스·입자 배열과 재질 초기값은 메모이제이션합니다. 프레임 루프는 ref·셰이더 uniform·그룹 회전만 갱신합니다. 프레임당 React 상태 갱신이나 새 객체·배열·재질 생성을 하지 않습니다. 진단 UI만 약 1.2초 간격으로 활성 프레임의 평균을 전달합니다.
- 시간은 delta에 기반합니다. 30/60/120fps의 동일한 시간 진행을 자동 검사했고, 0.1초를 넘는 간격은 복귀 시 순간 이동을 막기 위해 제한합니다.
- 비활성 탭은 `frameloop="never"`, 움직임 감소는 `"demand"`, 일반 상태는 `"always"`입니다. 시스템 `prefers-reduced-motion`은 수동 설정과 함께 적용하며 시스템 설정을 덮어쓰지 않습니다. 움직임 감소에서도 사용자가 명시적으로 드래그하여 시점을 바꿀 수 있습니다.
- 직접 소유한 BufferGeometry와 후처리 전체 그래프는 교체·해제 시 dispose합니다. Strict Mode의 즉시 effect 재실행은 동일 객체의 정리를 한 태스크 동안 유예해 중복 사용 중 폐기를 피합니다. Canvas·재질·컨트롤·프레임 구독은 Fiber/Drei의 해제 흐름을 사용하고 DOM/미디어 이벤트 구독도 제거합니다.
- WebGL 2 지원을 확인한 뒤 Canvas를 생성합니다. 미지원·컨텍스트 손실·셰이더 오류·렌더러 오류에는 정적인 빛 대체 화면과 재확인 버튼을 제공합니다. 대체 화면을 3D 검증 결과로 취급하지 않습니다.
- FPS 목표는 일반 데스크톱에서 60에 가까운 안정적인 관찰이지만 달성했다고 주장하지 않습니다. 패널의 FPS도 실제 브라우저에서 측정될 때만 표시합니다.

## 브라우저에서 확인할 항목 — 미검증

1. 네 프리셋의 색상과 미학, 넓고 얇은 커튼의 접힘과 앞뒤 깊이, 리본 간 투명한 혼합. 평면 스펙트럼이나 네온 선처럼 보이지 않는지 확인합니다.
2. 드래그 시 먼 성운·리본·앞 유리의 시차, 카메라 범위·모바일 프레이밍을 확인합니다. 리본은 공전하지만 카메라는 자동 회전하지 않습니다. 기본/역동 모드의 부드러운 공간 이동·파동·곡률 변화와 갑작스러운 움직임이 없는지 확인합니다.
3. Bloom 켜기/끄기, 저사양 8비트 경로와 HDR 경로, ACES 처리와 색상·어두운 공간의 대비, 과도한 백색·과포화 여부를 확인합니다.
4. 리본 2/3/4개와 레이어별 켜기/끄기, 교차 부분의 투명도 정렬·뒤집힘·Z-fighting·유리 면 하이라이트를 확인합니다.
5. 데스크톱·iPad·휴대폰의 세 품질, 가로/세로 전환, 패널 접기·스크롤·키보드 포커스·터치 드래그를 확인합니다.
6. 탭 비활성·복귀와 시스템/수동 움직임 감소를 확인합니다. 정적 모드에서 불필요한 연속 RAF가 없는지 점검합니다.
7. WebGL 2 비지원·실패·컨텍스트 손실·그래픽 재확인 흐름을 확인합니다. 실제 셰이더 컴파일·모바일 드라이버 호환성은 아직 확인하지 못했습니다.
