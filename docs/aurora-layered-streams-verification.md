# Aurora Lab · 넓은 리본과 중첩 에너지 흐름

작업일: 2026-10-14. 브랜치: `feat/glass-nebula-aurora`.

## Aurora Prototype V1 보존 상태

이 구현은 5단계 개인화 통합을 위한 시각적 초안으로, 추가 디자인 수정 없이 **Aurora Prototype V1** 체크포인트에 포함합니다. 카메라를 위쪽으로 회전할 때 리본 형태와 겹침이 어색한 문제, 일부 시점의 투명 자기 교차와 곡면 어색함이 남아 있습니다. 실제 GPU의 장시간 FPS·발열·메모리 검증도 아직 완료되지 않았습니다. 전체 보존 범위와 알려진 한계는 [V1 체크포인트 기록](./aurora-lab-verification.md#aurora-prototype-v1-체크포인트)을 따릅니다. 아래는 이번 시각 개선 작업 당시의 구현·검증 기록입니다.

## 변경 결과

이번 변경은 기존 미커밋 `/aurora-lab`을 이어서 리본 단면과 에너지 발생 방식을 개선합니다. 질문·캡슐·Q10·승인·분석 API·기존 결과 화면은 변경하지 않습니다.

- 주요 폐곡선 리본의 **띠 단면 폭 +28%**, 보조 Möbius-like 리본 **+30%**입니다. 지오메트리의 `height`가 실제 띠 폭이며 중심선의 타원 반경인 `width`는 유지합니다. 중심 구도와 닫힘을 보존하면서 띠를 넓혔습니다.
- 주요 미스트의 전체 폭은 이전 미스트 대비 **+34%**입니다. 보조 미스트는 겹에 따라 **약 +34~36%**입니다. 횡단 곡률과 깊이 간격도 넓혀 더 풍성한 부드러운 경계를 만듭니다. 정점 수·추가층 수는 늘리지 않습니다.
- 각 리본에 **독립 에너지 채널 3개**를 둡니다. 각 채널은 개별 휴지기를 가지며 동시에 1~3개가 보일 수 있습니다. 잠시 모두 쉬는 경우도 있지만 이전 단일 흐름보다 발생이 잦습니다.
- 채널의 기준 주기는 에너지 시간 **16~22초**입니다. 시작 지터를 매번 새로 계산하므로 실제 발생 간격도 불규칙합니다. 이전의 단일 22~31초 주기에서 세 독립 채널로 바뀌었습니다.
- 각 발생마다 시작 offset·길이·이동 속도·세기·시작/강조 위치·방향·잔광 폭/강도/감쇠를 리본/채널 시드와 발생 인덱스로 결정합니다. 같은 시드/시간은 같은 결과를 재현합니다. 과거처럼 같은 이벤트가 그대로 반복되는 고정 패턴은 아닙니다.
- 기본 이동 속도 **0.065~0.12회전/에너지 초**는 유지하고, 발생별 변동은 **±4%**로 제한합니다. 공통 에너지 클록과 리본 자체의 공간 운동 속도는 바꾸지 않았습니다. 활기는 속도 증가보다 빈도/중첩으로 만듭니다.
- 공통 호흡은 강한 밝기 게이트에서 **±6%의 약한 변화**로 줄였습니다. 개별 채널의 시작과 휴지기가 실제 리듬을 결정하므로 모든 리본이 같은 박자로 어두워지지 않습니다.

에너지 시간은 기존 프리셋 `flow`에 따라 적분하는 단위이므로 위 초와 실제 벽시계 시간은 다를 수 있습니다. 발생마다 8.5~10초 기준의 부드러운 흐름 구간을 사용하고 길이는 ±7% 변동합니다. 잔광 종료까지는 실제 구간 길이의 약 115~130%입니다. 이벤트는 다음 슬롯 전에 끝나도록 범위를 제한해 새 랜덤 속성으로 바뀔 때 밝기가 끊기지 않습니다.

## 구현과 비용

`aurora-energy.ts`에서 채널 프로필 3개를 한 번 만들고, 발생 슬롯이 바뀔 때만 정수 해시로 이벤트를 계산합니다. 이벤트 저장소는 ref에 재사용하며 GPU timing/shape/wake 벡터도 이벤트 시작 시에만 갱신합니다. 프레임마다 새 프로필/배열/React 상태를 만들거나 프래그먼트마다 랜덤 해시를 반복하지 않습니다.

GPU는 기존 시간 uniform으로 각 채널의 부드러운 Gaussian 흐름·잔광을 이동시킵니다. 빛은 단순 합산 대신 **`1 − ∏(1 − 값)`**으로 겹칩니다. 흐름과 잔광 계수를 각각 0~1 안에 유지해 세 흐름이 겹쳐 밝기가 세 배가 되는 것을 억제합니다. 이 상한은 각 리본의 에너지 계수에 대한 것이며 여러 투명 리본의 전체 화면 밝기를 보장하는 수치는 아닙니다.

본체와 안개는 같은 시드/이벤트를 사용해 흐름이 서로 어긋나지 않습니다. 폐곡선 연결부·양면 표현·경계 감쇠·현재 팔레트·Bloom·중심장·별/성운/유리·카메라/패널을 유지합니다. 외곽이 넓어져 카메라 안전 영역만 소폭 확장했고 최소 거리/카메라 속도/복귀 정책은 유지합니다.

low/balanced/high의 기존 정점·미스트 층·입자·유리·DPR·Bloom 예산을 유지합니다. 모든 기기에서 선택 품질을 그대로 적용합니다. 채널 수가 세 개라 Gaussian 계산은 늘었으며, 휴지기 채널은 계산을 일찍 종료합니다. 이것이 실기기 FPS 유지의 증거는 아닙니다.

### 브라우저

기존 `127.0.0.1:3000/aurora-lab`에서 Chromium 156 / ANGLE SwiftShader 소프트웨어 WebGL 2로 실행했습니다. 외부 및 `/api/` 요청을 차단했습니다. 프로젝트 의존성·서버/잠금·환경변수·폰트 파일을 바꾸지 않았고 검증 도구/캡처는 `/tmp`에만 있습니다.

- 실제 세 채널 GLSL 함수를 **160개 표본**으로 CPU 곡선과 비교했습니다. RGBA8 양자화 포함 최대 오차 **0.001946**, WebGL 오류 **0**입니다.
- 렌더러의 공간 시간을 8.3에 고정하고 테스트 계측으로 각 리본에 해당하는 실제 이벤트 데이터를 draw 직전에 넣어 **8.3/10.3/103.4/106.4 에너지 위상**을 캡처했습니다. 103.4는 주요 리본 하나에 세 흐름이 중첩되는 시점입니다. 제품에는 이벤트/시간 조절용 디버그 API를 넣지 않았습니다.
- 같은 중첩 위상에서 **low/balanced/high의 정면·측면·후면 9장**을 직접 비교했습니다. 띠와 미스트가 더 풍성하고 밝은 구간이 여러 곳에 분산되며 닫힌 윤곽·중심 구도·팔레트가 유지됩니다. 각 품질의 page/console/crash 목록은 비어 있고 WebGL 오류는 0입니다.
- 캡처/결과: `/tmp/aurora-layered-visual/`. 공간 고정 위상 비교와 GLSL 곡선 검증이며 여러 전체 주기의 연속 동영상 검증은 아닙니다.

재현: 실행 중인 로컬 서버와 별도 Playwright/Chromium 환경에서 다음 명령을 사용합니다.

```sh
AURORA_PLAYWRIGHT_MODULE=/path/to/playwright \
AURORA_CAPTURE_ENERGY=1 AURORA_CAPTURE_QUALITY=1 \
AURORA_BROWSER_OUTPUT=/tmp/aurora-layered-visual \
node tests/helpers/verify-aurora-viewer.mjs
```

두 캡처 플래그를 생략한 기존 카메라 회귀도 다시 실행해 통과했습니다. 정면·측면·후면·사선/360° 탐색·수직/줌 제한·패널 격리·정면 복귀·자동 공전/직접 조작 중단/재개·움직임 감소·모바일 핀치·공유 클록 보존을 확인했습니다. 최종 WebGL 오류는 0이고 page/console/crash 오류 목록은 비어 있습니다. 결과/캡처는 `/tmp/aurora-layered-camera-visual/`에 있습니다.

## 남은 한계와 보존 범위

미스트는 곡면 층으로 만든 볼륨 근사입니다. 일부 접힌/얇은 실루엣과 투명 자기 교차는 남습니다. 새 빈도·중첩은 더 살아 있는 느낌을 주지만 모든 순간에 모든 리본이 반드시 밝은 것은 아닙니다. 실제 GPU의 FPS·고밀도 DPR·메모리·발열·배터리·장시간 전환은 미검증이며 소프트웨어 캡처는 성능 보장이 아닙니다.

기존 질문·캡슐·Q10·AI 문장 승인·분석 API·기존 결과 화면은 수정하지 않았습니다. High Fidelity First, 시스템/수동 움직임 감소, 자유 탐색/자동 공전/정면 복귀/패널 옵션을 유지합니다. 커밋·푸시·배포·브랜치 전환·master/백업·리뷰 ZIP·환경변수 변경 없이 독립 실험 단계에서 종료합니다.
