# Aurora Lab · 360도 시각 품질 개선

작업일: 2026-10-14. 브랜치: `feat/glass-nebula-aurora`.

후속 [폐곡선 에너지 흐름](./aurora-energy-flow-verification.md)에서 주요 리본의 열린 형상을 닫힌 루프로 바꾸고 공간 운동을 줄이며 국소 흐름/잔광을 추가했습니다. 아래는 측면 품질 보정 당시의 기록입니다. 품질 예산과 카메라 조작 정책은 유지하며 최신 움직임·형태·안전 외곽·검사는 후속 문서를 따릅니다.

## 1. 개선 내용

기존 Glass Nebula Aurora와 Cinematic Orbit Viewer를 재사용하여 `/aurora-lab`의 리본·안개·유리 조각만 개선했습니다.

- **low**: 독립 리본 분할을 56×8에서 64×10으로 소폭 높이고, 폭 방향에 얕은 곡률을 추가했습니다. 리본당 32×6 보조 안개층 1장을 둡니다. 연결 루프는 48×10, 루프 안개는 40×6으로 보강했습니다. 가장자리와 접힌 면이 딱딱하게 읽히는 대비를 함께 낮춥니다.
- **balanced**: 독립 리본은 112×16, 보조 안개는 50×8입니다. 루프는 84×14, 루프 안개는 56×8 2겹입니다.
- **high**: 기존 독립 리본 160×20은 유지하고 폭 곡률/각도 보정/72×10 보조 안개를 추가했습니다. 루프는 120×14, 루프 안개는 80×8 2겹으로 보강했습니다. 이미 충분한 본체 길이 분할을 무조건 늘리지 않았습니다.
- 앞뒷면에 동일한 절댓값 시선·법선 응답을 적용합니다. 비스듬한 시점에서는 코어/가장자리 발광과 본체 농도를 완만하게 줄이고, 기존 노이즈로 밝은 판 같은 실루엣을 부분적으로 녹입니다. UV 미분(`fwidth`)을 반영한 경계와 낮은 알파의 점진적 감쇠로 작은 면의 딱딱한 끊김을 줄입니다.
- 보조 안개는 본체와 같은 중심·pose·위상·팔레트를 사용하지만 넓이와 횡단 곡률이 다릅니다. 두 평행 판을 복제하는 대신 얕게 부푼 빛막으로 깊이를 보완합니다. 루프의 반 꼬임 연결부는 유지합니다.
- 유리 조각 수 8/12/18은 유지하면서 중심 주변 타원 분포와 세 반경층으로 재배치했습니다. 전후좌우 모두에 조각이 있고 카메라를 따라 위치를 바꾸지 않습니다. 작은 인스턴스 풀은 시선 깊이에 따라 뒤에서 앞으로 정렬하며 색·위상도 함께 이동합니다.
- 추가 안개층의 외곽을 포함하도록 카메라 안전 영역만 소폭 넓혔습니다. 기본 리본 3개, 800×600의 정면 거리는 25.32에서 25.74로 약 1.6% 늘어납니다. 카메라 모드/속도/복귀/입력 제어는 변경하지 않았습니다.

## 2. 구현 이유와 비용

문제는 저해상도만이 아니었습니다. 기존 독립 리본은 폭 방향이 거의 선형이고, 비스듬한 면에 Fresnel 발광이 더해져 접힌 면이 선명해졌습니다. high에서도 보이는 면의 끊김은 정점만 늘려 해결할 수 없습니다. 곡률·부드러운 경계·각도별 농도·저밀도 안개를 함께 적용했습니다. 정면 팔레트와 코어 기본 계수, Bloom 설정은 유지하고 독립 본체 알파만 5% 낮춰 추가층의 누적 밝기를 억제합니다. 새 순백색 광원을 넣지 않습니다.

안개는 같은 GPU 정점 변형을 공유합니다. 안개 프래그먼트에서는 본체의 추가 grain fBm·필라멘트·코어 계산을 건너뜁니다. 한 리본에 안개층을 여러 장 추가하지 않습니다. 최악의 풀(독립 4개 + 루프 2개 + 모든 안개)은 다음과 같습니다. 비활성 루프는 저장소만 유지하고 GPU draw를 생략합니다.

| 품질 | 총 정점 | 활성 리본/안개 draw 최대 | 유리 draw |
|---|---:|---:|---:|
| low | 5,436 | 12 | 1 |
| balanced | 14,122 | 14 | 1 |
| high | 23,282 | 14 | 1 |

정점과 draw/overdraw 비용은 이전보다 늘었습니다. 상한과 안개 계산 생략은 비용을 관리하는 설계이며 실제 GPU FPS 개선을 의미하지 않습니다. 유리 정렬은 최대 18개만 기존 저장소에 삽입 정렬하고 카메라 행렬/팔레트가 바뀔 때만 GPU 버퍼를 갱신합니다. 정적인 카메라에서 매 프레임 정렬/업로드하지 않습니다. 정렬 자체에서 새 배열·벡터·React 상태를 만들지 않습니다.

**High Fidelity First**: 기기 종류나 화면 크기로 품질을 낮추지 않습니다. 선택한 low/balanced/high의 동일 예산을 모든 기기에 적용합니다. 입자 수·DPR·Bloom 예산과 기존 품질 UI는 유지합니다. 모바일은 기존 카메라의 화면 비율 프레이밍만 적용합니다.

## 4. 검증

- `npx tsc --noEmit --incremental false`, `npm run lint`: 통과.
- 자동 테스트 **135개** 통과: 기존 129개 + 품질 회귀 6개. 카메라 15·오로라 데이터 34·품질 6·문장 생성 53·Q10 19·질문/물리/하늘 8입니다. 실제 API는 모의 처리하며 OpenAI 비용 발생 호출은 없습니다.
- 신규 검사는 low의 실제 곡면 근사 최대 오차가 이전 분할보다 최소 10% 줄었는지, 횡단 곡률·안개 pose 공유/유효 삼각형·32개 관측 방향의 유리 분포·결정성/입력 검증·정면/측면/후면/기울어진 시점의 깊이 정렬을 확인합니다.
- 카메라 검사에서는 새로운 독립 안개를 포함한 모든 프리셋/리본 수/비교 강도의 곡면 표본이 안전 외곽 안에 있는지 확인합니다. 닫힌 루프 연결부/접선·중심 유지·장시간 위상·기기 독립 품질 검사도 유지합니다.
- `git diff --check` 및 미추적 변경 파일 공백 검사: 통과. 기존 추적 파일 diff는 없습니다.

### 브라우저

기존 `http://127.0.0.1:3000/aurora-lab` 서버와 Chromium 156/ANGLE SwiftShader 소프트웨어 WebGL 2를 사용했습니다. 프로젝트 의존성·서버 프로세스·잠금 파일은 변경하지 않았고 외부 및 `/api/` 요청을 차단했습니다.

동일한 시간 8.3초, 800×600/DPR 1에서 low/balanced/high의 정면·측면 90°·후면 180° 총 9장을 변경 전·후 각각 캡처하고 직접 비교했습니다. 캡처는 움직임 감소로 시간을 고정했으며 선택 품질/진단 수치가 각 단계에 그대로 유지됐습니다. page/console 오류는 없습니다.

- low: 측면의 날카로운 접힌 경계와 밝은 판의 대비가 줄고 곡면 외곽이 부드러워졌습니다. 한 장의 면이 접히는 윤곽 자체는 일부 남습니다.
- high: 본체와 루프가 같은 안개감 안에 섞이고, 측면·후면의 밝은 면 경계가 완만해졌습니다. 정면의 중심 리본·청록 팔레트·유색 코어는 유지됩니다. 뒷면까지 완전히 같은 형상/밝기를 만드는 효과는 아닙니다.
- 유리: low/high 모두 후면 캡처에서 조각이 보이고, balanced/high에서는 여러 위치·크기·깊이가 확인됩니다. 카메라를 따라 위치가 이동하지 않습니다.

기존 카메라 브라우저 회귀도 다시 실행해 통과했습니다. 자유 탐색/360°·수직/줌 제한·패널 격리·높이/거리까지 정면 복귀·자동 이동/조작 중단/명시적 재개·움직임 감소·모바일 구도/핀치·클록 보존을 확인했습니다. 최종 WebGL 오류는 0, page/console/crash 오류 목록은 비어 있습니다. 결과와 캡처는 `/tmp/aurora-quality-camera-recheck/`에 기록했습니다.

첫 카메라 검사에서는 자동 이동 확인 후 브라우저가 예기치 않게 종료됐습니다. 당시 페이지 오류는 없었고 종료 원인은 확정하지 못했습니다. 다른 검사 없이 단독 재실행한 최종 검사는 통과했습니다. 이 한 차례 종료 기록과 소프트웨어 환경의 결과를 장시간 안정성·누수 부재의 증거로 취급하지 않습니다.

품질별 캡처 재현(Playwright/Chromium과 로컬 서버 별도 준비):

```sh
AURORA_PLAYWRIGHT_MODULE=/path/to/playwright \
AURORA_CAPTURE_QUALITY=1 \
AURORA_BROWSER_OUTPUT=/tmp/aurora-quality-visual \
node tests/helpers/verify-aurora-viewer.mjs
```

변경 전: `/tmp/aurora-quality-before-visual/`, 최종 변경 후: `/tmp/aurora-quality-final-visual/`. 모든 검증 도구·브라우저 라이브러리·폰트는 `/tmp`에만 마련했습니다. 이 캡처의 DPR 1은 실기기의 고밀도 high 렌더링 성능 검증이 아닙니다.

## 5. 남은 한계

미스트는 얇은 곡면의 조합이며 실제 볼륨/ray marching은 아닙니다. 접선 시점에서 리본이 얇아지는 현상, 일부 접힌 면의 실루엣과 투명 자기 교차는 완전히 없어지지 않습니다. 유리끼리의 중심 깊이는 정렬하지만 리본 삼각형과 모든 유리 인스턴스를 완전히 교차 정렬하는 OIT는 구현하지 않았습니다. 셰이더의 작은 유리 부유 변위는 깊이 정렬에 반영하지 않으므로 거의 같은 깊이의 조각에는 오차가 남을 수 있습니다.

실제 모바일/태블릿/노트북 GPU의 balanced/high DPR·60FPS·GPU 메모리·장시간 반복 전환·발열·배터리는 미검증입니다. 소프트웨어 WebGL 캡처로 이를 보장하지 않습니다. 네 프리셋과 두 루프 강조 모드의 장시간 미학적 만족도도 실기기에서 확인해야 합니다.

## 6. 보존 범위
