## 범위와 데이터 계약

이번 단계는 **응답을 예술적으로 시각화하는 결정적 규칙 엔진**입니다. 심리 진단·성격 판정·질환·위기 추론을 하지 않습니다. 화면 통합, API 호출, 디자인·카메라·품질 예산 변경은 없습니다. 기존 질문·캡슐 물리·Q10 추천/문장 생성/승인·분석 API·기존 결과 화면·독립 `/aurora-lab`을 유지합니다.

추가 파일은 다음 네 개뿐입니다.

- `lib/aurora-personalization-types.ts`: 입력, 검증된 직접 입력 근거, 출력, 역할별 효과와 추적 정보 타입.
- `lib/aurora-personalization.ts`: 순수 계산 함수 `personalizeAurora(input, options?)`, 승인 제목 어댑터 `personalizeAuroraFromQuestionnaire(state, options?)`.
- `tests/aurora-personalization.test.mjs`: 계산·결정성·무결성·역할 분리·승인·회귀 검사.
- `docs/aurora-personalization-verification.md`: 공식, 적용 순서, 검증과 다음 단계 연결 범위.

입력 `selections`는 기존 질문 순서의 배열(Q1은 인덱스 0, Q9는 8)을 그대로 사용합니다. 각 행 내 선택 순서는 결과를 바꾸지 않습니다. `responses`는 `questionId`로 찾으므로 배열 순서와 무관합니다. 질문 행 자체를 바꿀 경우 질문 ID도 확인하여 잘못된 문항으로 합산하지 않습니다. Q10 행과 응답은 핵심 엔진에서 제외합니다.

출력 `appearance`는 기존 `AuroraAppearance` 타입 그대로입니다. 추가로 실제 근거만 포함한 `coreShares`, 네 가지 역할별 효과 계약, `inputState`, `trace`, `approvedTitle`을 제공합니다. 기기·화면 크기·GPU·품질을 입력으로 받지 않으며, 선택한 의미 비율은 모든 기기에서 동일합니다. 렌더링 품질 예산과 의미 계산을 분리해 High Fidelity First를 유지합니다.

## 입력 무결성과 직접 작성한 표현

고정 선택은 해당 질문의 고정 ID·label·원문이 일치해야 합니다. 고정 키워드의 의미는 항상 `KEYWORD_SEMANTICS`에서 가져오며 클라이언트의 `semanticWeights` 또는 별도 검증 레코드로 덮어쓰지 않습니다. 다른 질문의 ID, 변조된 고정 label/원문, 다른 질문 ID·answerIntent, Q1~Q9의 추천형 선택은 제외하고 이슈를 기록합니다.

직접 입력은 공백을 제외한 **정확한 label 일치와 원문 일치**가 같은 질문의 고정 표현에 있는 경우에만 그 매핑을 재사용합니다. 유사어·부분 일치·정규식·문구의 긍정/부정으로 의미를 추측하지 않습니다. 질문이 다르면 같은 문자열이어도 매핑을 공유하지 않습니다. 원본 `originalText`는 수정하지 않습니다.

알 수 없는 직접 입력의 raw `semanticWeights`는 구조가 정상이어도 의미가 검증되었다는 증거가 아니므로 기본적으로 무시합니다. 향후 검증된 의미가 생기면 신뢰하는 호출자가 `options.verifiedCustomMeanings`로 전달할 수 있습니다. 각 레코드는 질문 ID·선택 ID·**정확한 원문**에 묶이고, 1~2개의 서로 다른 유효 계열·primary/secondary 순서·유한 양수·합계 1을 검사합니다. 중복 검증 레코드, 잘못된 가중치는 제외합니다. 이 구조 검사는 의미 자체를 검증하지 않습니다. 신뢰하는 코드가 검증을 마친 레코드만 공급해야 하며 raw 클라이언트 값을 그대로 복사해서는 안 됩니다. 현재 UI에 이 옵션을 연결하지 않았습니다.

동일 문항의 같은 고정 키워드 또는 정규화한 같은 직접 입력은 하나의 근거로 묶고 선택 ID들은 추적에 보존합니다. 같은 표현의 중복 선택에 서로 다른 검증 의미가 있으면 해당 표현을 미분류로 처리합니다. 같은 문항 안의 중복 선택 ID는 제거해 순서에 따라 근거가 바뀌지 않도록 합니다.

## 핵심 색상 공식과 적용 순서

`AURORA_CORE_QUESTION_WEIGHTS`는 기존 `CORE_QUESTION_CONTRIBUTIONS`를 재사용하는 예술적 튜닝 상수입니다. 과학적인 심리 점수가 아닙니다.

1. `answered`인 핵심 문항에서 유효한 의미 매핑이 있는 고유 선택만 수집합니다. `pending`·`skipped`의 남아 있는 선택은 사용하지 않습니다. 미분류 표현을 0점의 의미로 바꾸지 않습니다.
2. 의미를 계산할 수 있는 핵심 문항 집합을 `A`라 할 때 문항 가중치는 `Wq = 기본 가중치(q) / Σ[A] 기본 가중치`입니다. 답변은 있으나 의미 매핑이 전혀 없는 문항도 추측하여 채우지 않고 계산에서 제외합니다. 해당 문항의 answered 상태와 미분류 선택은 그대로 기록합니다.
3. 문항 q의 매핑된 고유 선택 수를 `nq`, 각 선택 k의 기존 계열 가중치를 `w(k,f)`라 하면 `base(f) = Σq Wq × (Σk w(k,f) / nq)`입니다. 한 문항의 선택 개수가 많아져도 해당 문항 총 영향력은 `Wq`를 넘지 않습니다. 미분류 선택은 이 평균의 분모에 넣지 않습니다.
4. 각 계열 f에 양수 근거가 있는 **서로 다른 핵심 문항 수**를 `cq(f)`로 셉니다. 1차·2차 의미 모두 근거가 될 수 있습니다. 동일 문항 안의 여러 단어가 같은 계열이어도 한 번만 셉니다.
5. 반복 강조 `R(c)`는 근거 1개일 때 1.0, 2개 1.3, 3개 1.48, 4개 이상 1.6입니다. `emphasized(f) = base(f) × R(cq(f))`입니다.
6. `coreShare(f) = emphasized(f) / Σf emphasized(f)`로 다시 정규화합니다. 0보다 큰 실제 근거 계열만 남기고, 비중 내림차순·동률이면 기존 `SEMANTIC_FAMILIES` 순서로 정렬합니다.

예: Q1의 추진 단일 의미와 Q6의 탐색 단일 의미만 있으면 문항 비중은 각각 `0.18/0.47`, `0.29/0.47`입니다. 같은 의미를 다른 핵심 질문에서도 고르면 해당 계열에만 위 반복 강조를 적용하고 최종 합계를 다시 1로 맞춥니다.

반복된 문자열은 NFC·공백 정규화 기준으로 별도 추적합니다. 같은 단어의 반복과 서로 다른 표현에서 나온 같은 의미 계열의 반복은 다른 진단 정보입니다. **문자열 반복에 추가 배수를 적용하지 않습니다.** 동일 근거가 문자열·계열 반복으로 이중 강조되는 것을 피하기 위한 결정입니다. 문자열 반복 추적에는 핵심 색상에 참여한 선택만 포함합니다.

## 데이터 부족과 렌더러 호환

`pending`·`skipped`·`answered`를 구분합니다. answered인데 비어 있는 경우, 응답 레코드 누락/중복, 응답 상태와 선택이 모순되는 경우는 `trace.questions[].issues`에 남깁니다. 잘못된 응답 레코드는 pending으로 처리하고 선택을 계산에서 제외합니다.

`inputState`는 답변/건너뜀/대기 문항, 계산에 참여한 핵심 문항, 미분류 선택 ID를 제공합니다. `coreData`는 매핑된 핵심 문항이 0개이면 none, 1~4개이면 partial, 5개이면 complete입니다. complete는 응답 근거의 범위를 뜻하며 심리적 확신이나 모든 문항의 완료를 뜻하지 않습니다.

실제 의미 비중은 `coreShares`를 사용해야 합니다. 렌더러는 양수 비중의 2~7계열을 요구하므로 표현용 `appearance.palette`에는 다음 호환 규칙을 적용합니다.

- 실제 계열이 2개 이상: 그 비중과 기존 색상을 그대로 전달합니다. `visualFallback: none`.
- 실제 계열이 1개: 의미 비중은 `coreShares`에 1.0으로 유지합니다. 표시 팔레트만 실제 색 92%와 중립색 `#AEB9CC` 8%로 구성합니다. 중립 슬롯은 중복을 피하도록 grounding 또는 serenity ID를 사용합니다. `visualFallback: neutral-accent`와 `paletteOrigins`의 neutral-visual로 **색상 슬롯이 사용자 의미 근거가 아님**을 표시합니다.
- 실제 근거가 없음: `coreShares`와 계열 근거는 비웁니다. grounding/reflection 슬롯에 중립색 `#AEB9CC`/`#91A6BE`를 50%씩 사용합니다. 모든 슬롯을 neutral-visual로 표시하고 `visualFallback: neutral-palette`로 기록합니다. 이 두 ID는 기존 렌더러 호환 슬롯이며 사용자의 선택 계열로 해석하면 안 됩니다.

`appearance.motion`은 실제 핵심 비중으로 계열별 표현용 파라미터를 가중 평균합니다. 상수 범위는 speed 0.28~0.42, amplitude 0.48~0.76, flow 0.35~0.65, intensity 0.88~1.04입니다. 근거가 없으면 `{ speed: .32, amplitude: .58, flow: .45, intensity: .90 }`를 사용합니다. 특수 문항 값을 motion에 섞지 않습니다. 리본 수는 실제 계열 1개일 때 2, 2~3개일 때 3, 4개 이상이면 4이며, 중립 기본은 3입니다. 모두 `validateAuroraAppearance()`의 제약 안에 있습니다.

## 특수 효과 데이터 계약

이 값들은 이번 단계에서 렌더러에 적용하지 않는 **향후 표현용 파라미터**입니다. 각 계약에는 해당 질문·answerIntent·응답 상태·활성 여부·역할 안에서의 의미 비중·매핑/미분류 개수가 있습니다. 역할별 비중에도 문항 안의 고유 선택 평균을 사용하고 핵심 반복 배수는 적용하지 않습니다.

- `atmosphere`: Q3의 14개 고정 풍경 ID에 명시된 mistDensity·brightness·softness·spread를 평균합니다. 예를 들어 ‘짙은 안개’는 높은 안개 밀도의 표현일 뿐, 질환·위험·고정 성격이 아닙니다. 사용자 정의 표현이 같은 ID를 사용해도 정확한 고정 매핑이 없으면 풍경 효과를 만들지 않습니다. 검증된 커스텀 의미가 있어도 새로운 풍경 수치를 추측하지 않아 중립 파라미터·inactive로 유지합니다. `parametersOrigin`이 명시적 풍경인지 중립인지 구분합니다.
- `innerPulse`: Q7의 바라는 감정을 역할별 색 비중과 약한 glow·breathAmplitude·periodSeconds로 계약합니다. 활성값 glow 0.16~0.22, 호흡 진폭 0.06~0.10, 주기 14~18초입니다. 현재 성격이나 실제 충족 상태를 나타내지 않습니다.
- `releaseFragments`: Q8의 대상은 중심 바깥으로의 방향(radial-outward)·낮은 outwardSpeed(0.06~0.10)·fadeRate(0.05~0.07)·spread(0.35~0.50)에만 활용합니다. 개수나 진단적 심각도 점수로 바꾸지 않습니다.
- `outerExpansion`: Q9의 미래 방향은 outward 방향·rate(0.08~0.14)·reach(0.30~0.50)·coherence(0.50~0.65)로 전달합니다. 이미 갖춘 능력으로 해석하지 않습니다.

무응답·건너뜀·미분류만 있는 경우 효과는 inactive입니다. Q7~Q9의 광량/이동값도 0으로 남기며 Q3는 명시적인 중립 기본 파라미터를 제공합니다. 소비자는 inactive를 존중해야 합니다.

## 승인 제목과 추적

`personalizeAurora()`의 제목은 항상 null입니다. `personalizeAuroraFromQuestionnaire()`만 기존 `getApprovedClosingMessage()`를 호출하여 현재 입력 fingerprint와 일치하는 승인 문장의 `{ text, source }`를 복사합니다. 초안·직접 입력만 있는 상태·승인 전 수정·오래된 승인은 제목이 되지 않습니다. 승인 제목은 팔레트에 영향을 주지 않습니다. 실제 화면에 제목을 표시하지 않았습니다.

trace는 질문별 상태·역할·기본/유효 가중치, 선택별 원래 키워드/선택 ID·매핑 출처·primary/secondary 가중치·반복 강조 전 기여도, 계열별 base·근거 문항·반복 배수·강조 후 점수·최종 비중을 제공합니다. 원문·label·전체 승인 fingerprint는 출력 추적에 복사하지 않고 ID로 원래 상태에서 찾습니다. 서버·콘솔·분석 로그를 추가하지 않습니다. 제목 자체는 개인적인 승인 텍스트이므로 후속 소비자도 불필요하게 로그에 남기지 않아야 합니다.

함수는 입력과 원본 선택 객체를 바꾸지 않습니다. 출력 가중치도 복사합니다. 현재 시간·`Math.random()`·네트워크 요청을 사용하지 않고 정렬 순서와 질문 처리 순서를 고정합니다. 동일 입력이면 전체 출력이 동일합니다.

## 자동 검증
