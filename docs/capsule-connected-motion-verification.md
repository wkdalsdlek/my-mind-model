# 연결된 관성·유리 파편·빛 꼬리 검증

검증일: 2026-10-13(한국 시간). Chromium 156.0.8078.4, 로컬 개발 페이지와 CPU 렌더러를 사용했습니다.

## 구현과 원인

- 기존 관성은 최대 170px/s·1.8초·감쇠율 1.65로 제한됐습니다. 일반 모드에서 최대 210px/s·3.2초·감쇠율 1.05로 강화했습니다. 놓는 속도는 최근 포인터 속도에서 계산하며 `(속도 - 60) × 0.48`을 사용합니다. 거리를 직접 지정하지 않습니다.
- 낮은 입력 빈도에서는 120ms 창의 모든 과거 점이 제거돼 이동 중인데도 속도가 0이 되는 문제가 있었습니다. 창 직전의 한 점을 보관하고 경계 위치를 보간해, 불규칙한 입력 간격에서도 속도를 계산합니다. 오래 멈춘 뒤 놓으면 추가 운동량은 0입니다.
- 자유 부유 조향을 감속 구간 동안 점차 늘립니다. 관성 종료 후에도 기존 자유 부유로 연결됩니다. 내부 계산 단계는 최대 1/120초입니다.
- 관성 경계 반발은 속도의 68%, 관성 캡슐 충돌의 상대 반발 계수는 0.64입니다. 밀어놓은 캡슐이 정지한 캡슐에 부딪히면 더 가볍게 반응하고, 운동량을 받은 캡슐도 짧은 이동 구간을 가집니다. 느린 자유 부유의 기존 반응은 유지합니다.
- 기존 꼬리는 드래그 이벤트에서만 생성됐고, 하나의 전역 이전 좌표를 사용해 여러 캡슐과 충돌 후 방향 변화에 연결되지 않았습니다. 이제 같은 MotionEmitter가 드래그와 실제 물리 몸체의 이동을 전달합니다.
- 시각 점검 중 짧은 선 조각들이 분리돼 보이는 문제를 확인했습니다. 이전 이동 지점과 중간점을 잇는 SVG 이차 곡선으로 교체했습니다. 캡슐별 기록을 사용하고 마스크로 캡슐 아래를 가려 텍스트를 보호합니다. 캡슐 뒷면에서 생성되며 충돌 후 바뀐 속도 방향을 이어받습니다.

## 설정값과 상한

| 항목 | 이전 | 변경 후 일반 모드 |
| --- | --- | --- |
| 관성 속도 상한 | 170px/s | 210px/s |
| 관성 전달 계수 | 0.32 | 0.48 |
| 관성 감쇠율 | 1.65/s | 1.05/s |
| 관성 구간 | 1.8초 | 3.2초 |
| 충돌 파편 | 6~12개 | 12~20개 |
| 파편 크기 | 주로 2~4.5px | 2~6px |
| 파편 수명 | 450~750ms | 700~1000ms |
| 파편 확산 거리 | 12~54px | 28~128px |
| 충돌 발광 | 없음 | 160ms |
| 꼬리 수명 | 330ms | 900ms |
| 꼬리 밝기 | 최대 opacity 0.3 | 최대 opacity 0.85 + 밝은 중심선 |
| 꼬리 두께 | 3px | 최대 8.5px, 나이에 따라 감소 |

- 파편은 접촉 법선을 따라 양쪽으로, 경계에서는 안쪽으로 퍼집니다. 점·짧은 유리 조각·삼각 파편·밝은 가루를 섞고 충돌한 두 캡슐의 색을 반영합니다.
- 위치 keyframe의 구간 속도를 줄여 빠르게 튀어나온 뒤 감속합니다. 번개나 전기 아크는 사용하지 않습니다.
- 파편 풀은 최대 80개, 짧은 발광은 최대 3개입니다. 전체 300ms·동일 충돌 850ms 쿨다운을 유지합니다. Popover 최상위 레이어에서 캡슐 앞에 표시합니다.
- SVG 잔상은 최대 48개 구간을 재사용합니다. 일반 모드의 빠른 단일 경로는 32ms 간격·900ms 수명으로 약 20~28개 구간을 목표로 합니다. 여러 캡슐은 전체 풀을 공유합니다.
- 헤일로·색 리본·밝은 중심선·작은 가루를 겹치고, 오래된 구간은 가늘어지며 투명해집니다. 포인터를 놓아도 경로를 지우지 않아 관성 꼬리가 이어집니다. 속도가 22px/s 아래로 줄면 새 꼬리는 생성하지 않고 기존 구간만 사라집니다.
- 저밀도 모드는 파편 최대 14개(풀 48), 잔상 풀 28구간·수명 700ms입니다. 논리 CPU 수가 4 이하이거나 긴 프레임이 누적되면 선택합니다. 전환 시 기존 효과는 자연스럽게 끝납니다.
- 움직임 감소 모드는 관성 최대 45px/s·0.9초, 파편 8개·500ms·짧은 확산, 잔상 풀 16구간·400ms를 적용하며 충돌 발광을 생략합니다. 기존 부유 멈추기는 물리와 효과 모두에 적용됩니다.

## 동일 조건 계산 비교

수정 전 코드를 /tmp에 보관해 현재 코드와 비교했습니다. 같은 시작 좌표 (300,250), 155×52 캡슐, 1400×800 공간, 같은 의미 그룹·위상·입력 속도, 1/120초 간격을 사용했습니다. 아래 값은 **계산 테스트**이며 브라우저 실측과 구분합니다.

| 포인터 속도 | 이전 초기 속도 / 거리 | 변경 후 초기 속도 / 거리 |
| --- | --- | --- |
| 250px/s | 60.8px/s / 33.70px | 91.2px/s / 79.36px |
| 600px/s | 170px/s / 92.02px | 210px/s / 178.33px |
| 1200px/s | 170px/s / 92.02px | 210px/s / 178.33px |

각 버전의 관성 구간 끝까지 측정했습니다(이전 1.8초, 변경 후 3.2초). 입력 600px/s에서 거리는 약 1.94배, 지속시간은 약 1.78배 증가했습니다.

30/60/120fps로 외부 갱신 빈도를 바꾼 계산에서는 모두 178.33px로 일치했습니다. 캡슐에 충돌한 뒤 속도 부호가 반전되는 계산 검증과, 간격 150ms의 입력에서도 올바른 속도 133.33px/s를 보존하고 정지 후 0이 되는 검증도 통과했습니다.

## 실제 브라우저 검증

### 관성

1440×900, 움직임 감소가 꺼진 환경에서 원본 중심을 프레임마다 측정했습니다. 관성 거리는 놓은 시점부터 약 3.2초 후의 중심 차이입니다.

| 입력 | 실제 이동 거리 | 관성 표시 유지시간 |
| --- | --- | --- |
| 느린 드래그 | 11.76px | 추가 관성 없음(기본 부유 이동 포함) |
| 빠른 드래그 | 172.88px | 약 3.15초 |

- Chromium의 native CDP 마우스 이벤트를 사용했습니다. 빠른 입력의 발생 시간을 지정해 자동화 IPC 지연으로 실제 입력까지 느려지는 문제를 분리했습니다. 실제 DOM 좌표를 측정했으며 CSS 존재 여부만 확인한 결과가 아닙니다.
- 해제 순간 위치 차이가 1px 미만이었습니다. 1.2초 이후에도 해당 캡슐의 관성 꼬리가 계속 생성됐습니다.
- 충돌/경계에 닿기 전후 실제 이동 방향과 해당 캡슐의 꼬리 각도를 관측했습니다. 0 부근과 ±π 부근이 모두 관측돼, 반발 방향으로 꼬리가 이어짐을 확인했습니다.

### 파편과 꼬리 시각 검증

- 저밀도 모드에서 접촉점 파편 14개, 일반 모드에서 20개를 확인했습니다. 일반 모드는 보고되는 CPU 수를 8로 설정해 분기를 검증했으며 실제 8코어 하드웨어 성능 측정은 아닙니다.
- 파편의 2~6px 크기와 700~1000ms 수명, 접촉점의 양쪽 확산 및 경계의 안쪽 확산을 확인했습니다. 파편 레이어가 최상위에 올라오는 것도 확인했습니다.
- 관성 중 실제로 캡슐 밖에 보이는 SVG 구간 10개와 약 118.7px의 꼬리 범위를 관측했습니다. 해당 시점·입력의 실측값이며 고정 길이가 아닙니다.
- 곡선 드래그에서는 활성 구간 5개의 방향이 -0.675~1.249rad로 달랐습니다. 연속 곡선과 캡슐 마스크를 스크린샷으로 시각 확인했습니다.
- 검토용 화면은 실제 발생한 효과를 한 프레임에 고정해 캡처했습니다. 고정은 검증 코드에서만 수행했습니다.
- 화면 파일: /tmp/mind-model-browser-check/strong-final-tail.png, strong-visible-curve.png, strong-boundary.png.

### 유지 기능

- 성공 답변 드롭은 관성 없이 선택됐습니다. 중복 선택, 같은 단어 생성, 삭제, 질문 왕복 후 답변 유지가 작동했습니다.
- 부유 멈춤 시 위치가 고정되고 잔상 생성·애니메이션이 멈췄습니다.
- 모바일 390px 및 iPad 810px 에뮬레이션에서 실제 touchStart/Move/End를 사용해 드래그, 놓은 위치 유지, 탭·중복·삭제를 확인했습니다.
- 16자 키워드 생성 후 모바일/iPad에서 각각 6초, 작은 모바일 320px에서 4초 관측했습니다. 둥근 외곽 겹침·영역 이탈·가로 넘침은 없었습니다.
- 브라우저 런타임 오류 없음. 실제 AI 요청은 차단했습니다.

## 남은 한계

- 이전에 확인한 prefers-reduced-motion=true 설정이 사용자 브라우저에 유지돼 있다면, 80~180px의 일반 모드 대신 위의 감소 모드가 적용됩니다. 이번 요청에 따라 시스템 설정을 존중합니다.
- 이동 거리와 꼬리 길이는 실제 입력, 충돌, 남은 공간, 프레임과 밀도 모드에 따라 달라집니다. 매우 낮은 FPS에서는 시뮬레이션 시간 제한 때문에 실제 재생 시간이 길어질 수 있습니다.
- 충돌은 2D 둥근 외곽의 근사와 스타일화한 운동량 반응입니다. 실제 유체·유리 강체의 정밀 시뮬레이션은 아닙니다.
- 많은 키워드에서 전체 충돌 쌍 비교 O(n²), SVG 마스크/곡선과 합성 비용이 증가합니다. 파편·잔상·마스크 수는 제한했지만 실제 RTX 3050 Ti FPS는 측정하지 않았습니다.
- 실기기 Safari·화면 회전 중 드래그·OS 수준 탭 숨김/복귀는 이번에 검증하지 않았습니다. 모바일/iPad 결과는 Chromium 에뮬레이션입니다.
- AI 분석과 결과 화면 코드는 보존했지만 실제 분석 응답과 결과 WebGL 실행은 이번 단계에서 재검증하지 않았습니다.
