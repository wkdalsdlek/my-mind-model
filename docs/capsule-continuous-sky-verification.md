# 속도 기반 관성·유리 가루·연속 하늘 검증

검증일: 2026-10-13(한국 시간). Chromium 156.0.8078.4의 CPU 렌더러로 로컬 질문 화면을 실행했습니다.

## 실제 원인

- 이전 관성은 포인터 속도를 8%만 전달하고 30px/s로 제한한 뒤, 감쇠율 3으로 약 1.1초 안에 줄였습니다. 빠르게 놓아도 이동 폭이 작았습니다.
- 이전 드롭은 놓은 위치가 다른 캡슐의 영역에 걸리면 그리드 탐색으로 빈 위치를 찾았습니다. 위치가 튀는 원인이 될 수 있었습니다.
- 이전 충돌은 12px 안전 간격을 가진 사각 경계에서 시작됐고, 이후에도 실제 둥근 외곽과 다른 접촉 근사를 사용했습니다. 십자 반사광 형태의 입자는 유리 가루보다 전기 스파크처럼 보일 수 있었습니다.
- 하늘은 시간대마다 서로 다른 고정 좌표의 가상 요소를 페이드했습니다. 광원의 DOM은 유지돼도 태양 하나가 이동하는 구조는 아니었습니다.

## 관성 및 위치 연속성

- 최근 120ms의 포인터 기록과 병합 이벤트 수집은 유지합니다. 입력 속도 60px/s 이하에는 추가 관성을 주지 않습니다.
- 속도 전달은 `(입력 속도 - 60) × 0.32`, 상한은 170px/s입니다. 이동 거리를 직접 지정하지 않습니다.
- 일반 환경은 약 1.8초 동안 지수 감쇠(율 1.65)를 적용하고, 자유 부유 조향을 점차 늘립니다. 최종 거리와 방향은 속도·남은 공간·충돌에 따라 달라집니다.
- 동작 감소 환경에서는 상한 45px/s, 짧은 0.9초 구간과 더 강한 감쇠를 적용합니다. 부유 멈추기는 관성에도 적용됩니다.
- 일반 드롭은 놓은 점을 유지하고, 드래그 중 고정한 몸체 주변의 다른 몸체를 분리합니다. 빈자리 탐색에 따른 원본 위치 점프를 제거했습니다.
- 영역 밖 드롭은 원본을 최상위 레이어에 유지한 채 속도와 복원 힘으로 경계 안쪽을 향하게 합니다. 들어온 뒤 원래 DOM 배치로 복귀합니다. 고정 거리의 위치 애니메이션은 사용하지 않습니다.
- 성공 답변 드롭은 기존 선택 및 원본 재사용 처리를 유지하며 추가 관성을 적용하지 않습니다.

## 둥근 접촉점과 유리 파편

- 각 캡슐을 중심 선분과 끝 반원으로 구성한 2D 둥근 외곽으로 계산합니다. 두 선분의 최근접점에서 표면 위치, 충돌 법선 및 침투량을 구합니다.
- 실제 둥근 외곽 가까이에서 반발하며 수치 안정성용 여유는 0.75px입니다. 경계 반발 역시 몸체가 실제 내부 경계에 닿았을 때 발생합니다.
- 상대 접근 속도에 따라 6~12개 입자와 퍼지는 거리를 정합니다. 양쪽 법선 방향에 작은 무작위 편차를 주며, 경계 법선은 항상 공간 안쪽입니다.
- 작은 점·짧은 조각·삼각 파편을 섞고 두 캡슐의 색을 번갈아 사용합니다. 번개선이나 전기 아크는 없습니다.
- 파편 위치 keyframe의 구간 속도가 점차 줄어들도록 계산합니다. 전체 시간은 선형으로 진행해 위치 감속 때문에 밝기까지 너무 빨리 사라지지 않도록 했습니다.
- 일반 수명은 450~750ms, 동작 감소 환경은 450ms와 짧은 확산 거리입니다. 최대 36개 DOM 노드만 재사용하며 전체 300ms·같은 충돌 850ms 쿨다운을 유지합니다.
- 일반 캡슐 앞에 렌더링하고, Popover가 가능한 브라우저에서는 입자 레이어도 최상위 레이어에 올려 드래그 캡슐보다 앞에 표시합니다. pointer-events를 차단해 입력을 가리지 않습니다.

## 하나의 가상 하늘

- 질문 진행도를 `(질문 번호 - 1) / 9`인 연속 시간으로 표현합니다.
- 태양·달·별의 노드를 항상 유지하고 현재 시간만 목표 시간으로 이동합니다. 왕복 전환 중에도 현재 위치와 속도를 이어받습니다.
- 시간 전환은 프레임 dt와 감쇠 스프링으로 계산합니다. 태양이 갑자기 가속하지 않도록 진행 속도를 제한합니다.
- 태양은 낮은 아침 위치 → 높은 점심 위치 → 낮은 저녁 지평선의 곡선을 따릅니다. 같은 시간값에서 색·크기·밝기와 대기광도 함께 계산합니다.
- 해가 질 때 달이 아래쪽에서 올라오며 서서히 밝아집니다. 별은 8/12/16개의 세 그룹을 서로 다른 시간에 밝게 해 전체 36개가 점차 드러나도록 했습니다.
- 질문을 바꾸거나 역방향으로 이동해도 태양·달 DOM과 현재 시간은 유지됩니다.
- 부유 멈추기와 탭 숨김은 하늘 루프에도 적용합니다. 돌아온 첫 프레임의 시간 차이를 초기화해 숨겨진 시간을 한 번에 따라잡지 않습니다. 동작 감소 설정에서는 이동 속도를 더 줄입니다.

## 실제 브라우저 검증

### 느린 입력과 빠른 입력

실제 페이지의 원본 DOM 중심을 약 2.1초 동안 프레임마다 측정했습니다. 이동 거리는 놓는 순간부터 약 1.8초 후까지입니다.

| 입력 | 실제 이동 거리 | 해제 순간 중심 위치 차이 |
| --- | --- | --- |
| 느린 드래그 | 5.83px | 0.0002px |
| 빠른 드래그 | 90.78px | 0.0002px |

- 초기 자동화의 작은 이동 이벤트는 IPC 지연으로 실제 포인터 속도도 느렸습니다. 이벤트 시간과 좌표를 확인한 뒤 빠른 입력 제스처를 조정했습니다. 위 값은 실제 빠른 포인터 입력 재검증 결과입니다.
- 공간 밖에 놓은 캡슐도 해제 시 중심 차이가 1px 미만이었고, 물리 이동으로 공간에 다시 들어온 뒤 최상위 레이어를 해제했습니다.
- 별도의 계산 테스트에서 입력 40/250/550/1000px/s의 약 1.8초 이동은 각각 6.01/33.86/85.13/92.18px였습니다. 계산 테스트와 실제 브라우저 측정은 구분합니다.

### 접촉점과 확산 방향

- 실제 캡슐 충돌에서 8개 파편을 관측했습니다. 법선 투영값에 양수와 음수가 모두 있어 양쪽 확산을 확인했습니다.
- 실제 경계 충돌에서 12개 파편을 관측했습니다. 법선이 (-1, 0)이었고 모든 파편의 법선 투영값이 양수여서 안쪽 확산을 확인했습니다.
- 세 형태, 충돌 강도에 따른 개수 차이, 450~750ms 수명을 확인했습니다. 자연 발생한 파편을 검증용으로 한 프레임에 고정해 스크린샷을 찍고 밝기·위치를 시각 확인했습니다. 프레임 고정은 앱 코드에 포함되지 않습니다.
- 최종 효과에서는 고정 프레임의 실제 opacity가 0.5 이상이었고, 캡슐 테두리 위에서도 파편을 읽을 수 있었습니다.

### 기존 기능·반응형·접근성

- 성공 드롭의 답변 수집, 중복 선택, 같은 단어 직접 생성, 삭제, 질문 왕복 후 답변 유지가 작동했습니다.
- 일반 화면의 추가 10초 좌표 관측에서 둥근 외곽의 겹침·경계 이탈이 없었습니다.
- 모바일 390px/iPad 810px는 각각 8초, 80회, 모바일 320px는 5초, 50회 좌표 측정했습니다. 긴 키워드를 포함한 상태에서 외곽 겹침·경계 이탈·가로 넘침은 없었습니다.
- iPad Chromium 에뮬레이션에서 실제 touchStart/Move/End로 드래그하고, 놓은 위치 유지와 동작 감소 관성 4.31px를 확인했습니다.
- headless Chromium은 다른 탭 활성화 후에도 document.visibilityState가 visible이었습니다. 따라서 실제 OS 탭 숨김 검증은 완료했다고 보고하지 않습니다. visibilitychange를 시뮬레이션한 검증에서는 진행도가 멈추고 복귀 후 재개했습니다.
- 800/350/304px 폭에서 각각 120초 계산 검증: 둥근 외곽 침투·경계 이탈 없음.
- Chromium 런타임 오류 없음. 실제 AI 요청은 차단했습니다.

## 검사 결과와 남은 한계

- `npx tsc --noEmit`: 통과.
- `npm run lint`: 통과(경고 없음).
- `git diff --check`: 통과.
- AI API, 결과 화면, 질문 데이터 및 의존성은 변경하지 않았고 실제 AI 응답과 결과 WebGL 실행은 이번에 재검증하지 않았습니다.
- 충돌 외곽은 기본 CSS 캡슐의 2D 둥근 모양에 맞춘 모델입니다. 유리 반사광·그림자·드래그 확대까지 포함하는 3D 물리 접촉은 아닙니다.
- 실제 이동 거리는 입력 속도와 충돌에 따라 달라집니다. 모든 빠른 드래그에 30~100px를 강제하지 않습니다.
- 매우 많은 키워드에서는 전체 쌍 비교 O(n²)과 합성 레이어 비용이 증가합니다. 입자·별 노드는 고정 수이며 새 물리/3D 라이브러리는 추가하지 않았습니다.
- 실제 RTX 3050 Ti 성능, 실기기 iPhone/iPad Safari 및 OS 수준의 탭 숨김/복귀는 검증하지 않았습니다.
- Popover가 없는 브라우저의 기본 입자 레이어는 일반 캡슐 앞에 표시되지만, body로 이동한 드래그 원본보다 앞에 표시되는지 이번에 재검증하지 않았습니다.
