# 짧은 관성·스파클·시간대 광원 검증

검증일: 2026-10-12. Chromium 156.0.8078.4, CPU 렌더러로 로컬 개발 페이지를 실행했습니다. 앞선 상호작용 검증 이후의 추가 개선 기록입니다.

## 수정한 파일

- components/questionnaire/capsule-inertia.ts: 최근 포인터 이동 기록과 놓는 속도 계산을 추가했습니다.
- components/questionnaire/useCapsuleDrag.ts: 합쳐진 포인터 이벤트도 수집하고, 답변칸 밖에 정상적으로 놓았을 때만 이동 속도를 전달합니다.
- components/questionnaire/useCapsulePhysics.ts: 놓은 속도를 기존 부유 몸체로 전달하고, 다시 잡으면 남은 관성을 해제합니다.
- components/questionnaire/capsule-physics.ts: 짧은 감속 구간과 자유 부유로의 점진적인 복귀를 추가했습니다. 크기가 다른 캡슐의 스파클도 유리 사이 간격에서 발생하도록 접촉 위치 계산을 개선했습니다.
- components/questionnaire/capsule-effects.ts: 스파클 개수·크기·밝기·지속시간을 강화했습니다.
- components/questionnaire/CapsuleQuestionnaire.module.css: 스파클 광택과 시간대별 추상 광원을 추가했습니다.

## 관성 구현

- 최대 24개, 최근 120ms 이내의 포인터 위치를 ref에 보관합니다. 포인터를 멈춘 뒤 놓으면 이전의 빠른 이동이 관성으로 남지 않습니다.
- 놓는 속도의 8%만 전달하며 최대 30px/s로 제한합니다. 매우 느린 이동에는 추가 관성을 주지 않습니다. 동작 감소 설정에서는 속도를 65%로 줄입니다.
- 1.1초 동안 기존 몸체 속도를 지수적으로 감쇠합니다. 같은 구간에서 자유 부유 조향 비중을 부드럽게 늘려, 감속 후 흐름에 다시 합류합니다.
- 별도의 이동 애니메이션이나 물리 엔진을 만들지 않았습니다. 기존 위치·속도와 경계/캡슐 충돌 계산을 그대로 사용합니다.
- 성공 드롭은 기존 선택 처리와 원본 재사용을 유지하며 추가 관성을 주지 않습니다. 취소·Escape 및 탭에도 추가 관성을 주지 않습니다.
- 기존 부유 멈춤 상태는 관성에도 적용됩니다.

## 스파클 강화

| 항목 | 이전 | 변경 후(일반 동작) |
| --- | --- | --- |
| 한 번에 발생하는 입자 | 3개 | 4개 |
| 고정 DOM 풀 | 6개 | 8개 |
| 중심 크기 | 3px | 4px |
| 반사광 길이 | 7px | 9px |
| 최대 opacity | 0.48 | 0.68 |
| 지속시간 | 360ms | 440ms |

- 6px의 작은 발광과 11px의 아주 약한 외곽 빛을 겹쳤습니다. 색상은 충돌한 캡슐의 색을 유지합니다.
- 전체 300ms, 같은 충돌 쌍/경계 사건 850ms의 쿨다운은 유지했습니다.
- 동작 감소 설정에서는 한 번에 3개, 최대 opacity 0.58, 280ms의 짧은 효과를 사용합니다.
- 크기가 다른 캡슐 사이에서도 표면 가장자리 사이에 효과를 놓아 캡슐 안쪽에 가려질 가능성을 줄였습니다.

## 시간대별 배경

- 1–2번 아침: 낮은 위치의 넓은 피치빛 광원, 블루·라벤더와 옅은 빛줄기를 사용합니다.
- 3번 전환: 기존 아침/점심 레이어 혼합을 유지합니다.
- 4–5번 점심: 높은 은빛 광원, 맑은 청록과 하늘빛, 넓고 밝은 조도 차이를 사용합니다.
- 6번 전환: 기존 점심/저녁 혼합을 유지합니다.
- 7–8번 저녁: 낮아진 따뜻한 광원과 수평 노을 띠에 로즈·오렌지·보라·골드를 섞습니다.
- 9–10번 밤: 딥 네이비·인디고에 작은 달빛 광원과 드문 별빛 입자를 추가합니다.
- 광원/별은 CSS 그라디언트와 가상 요소입니다. 추가 프레임 루프, 반짝임 애니메이션, 이미지 자산 또는 WebGL은 사용하지 않습니다.
- 배경 레이어는 질문 전환에도 유지됩니다. 기존 1250ms opacity 전환(동작 감소 설정 600ms)을 유지했습니다.
- 모바일 세로 배치에서는 광원 위치를 키워드 공간 쪽으로 옮깁니다.

## 실제 브라우저 검증

### 놓은 뒤 감속

실제 DOM 좌표를 놓는 순간부터 약 1.8초 동안 프레임마다 측정했습니다. 초기 속도는 약 0–250ms, 후반 속도는 약 650–1000ms의 평균입니다.

| 환경 | 초기 이동 속도 | 후반 이동 속도 | 첫 1초 이동 거리 |
| --- | --- | --- | --- |
| 일반 동작, 마우스 | 13.00px/s | 0.95px/s | 5.23px |
| 동작 감소, 마우스 | 8.29px/s | 0.71px/s | 3.47px |
| iPad 에뮬레이션, 동작 감소, 실제 터치 이벤트 | 5.29px/s | 0.44px/s | 2.24px |

- 터치는 Chromium DevTools의 touchStart/Move/End를 사용했습니다. 최초 터치 측정에서 감속 조건을 충족하지 못해, 놓기 직전의 검사 호출을 제거하고 관측기를 제스처 전에 설치한 연속 입력으로 재검증했습니다. 위 터치 값은 그 재검증 결과입니다.
- 답변칸 밖 드롭 후 짧은 이동과 감속, 정상 답변 드롭 1회 추가, 중복 선택, 삭제, 질문 이동 후 답변 유지가 작동했습니다.
- 계산 검증에서는 매우 큰 입력 속도도 상한을 넘지 않았고, 경계/다른 캡슐과 충돌한 관성이 기존 경계 계산을 거쳤습니다. 정지 후 놓으면 오래된 포인터 속도가 0이 되는 것도 확인했습니다.

### 효과·배경·반응형 화면

- 일반 동작 환경에서 실제 캡슐 충돌과 경계 접촉 스파클을 모두 관찰했습니다. 효과 관측에서 32회 방출, 최대 동시 실행 8개, 최소 방출 간격 307.4ms를 측정했습니다.
- 실행 중인 효과의 실제 크기 4px, keyframe opacity 0.68, 지속시간 440ms를 확인했습니다. 별도 페이지에서는 자연 발생한 효과를 한 프레임에 고정해 스크린샷을 캡처하고 실제 반사광을 시각 확인했습니다. 이 스크린샷 고정은 검증 코드에서만 수행합니다.
- 별도 20초 동안 200회 좌표를 관측해 겹침·영역 이탈이 없음을 확인했습니다.
- 질문 1~10의 시간대 순서와 배경 DOM 유지를 확인했습니다. 2 → 3번의 아침 opacity는 1.000 → 0.919 → 0.551로 바뀌어 실제 중간 전환을 관찰했습니다.
- 아침/점심/저녁/밤 스크린샷을 캡처하고 시각 확인했습니다. 광원 높이, 낮과 밤의 조도, 저녁의 따뜻한 노을, 밤의 별빛이 구분됩니다.
- 모바일 390px/iPad 810px는 각각 8초, 80회 좌표 측정했습니다. 모바일 320px는 5초, 50회 측정했습니다. 16자 키워드가 포함된 상태에서 겹침·영역 이탈·가로 넘침은 없었습니다.
- 모바일/iPad의 터치 탭·중복 선택·삭제·긴 새 키워드 생성이 작동했습니다. 화면 캡처로 배치도 확인했습니다.
- 브라우저 런타임 오류는 없었습니다.

## 정적 검사와 유지한 범위

- `npx tsc --noEmit`: 통과.
- `npm run lint`: 통과.
- `git diff --check`: 통과.
- 이번 작업 전후 app/page.tsx, 공통 레이아웃, AI API, 질문 데이터, package.json, lockfile 해시가 동일합니다.
- 기존의 미커밋 변경사항은 유지했습니다. API 키 파일은 읽거나 수정하지 않았고, 실제 AI 요청은 검증에서 차단했습니다.

## 성능과 남은 한계

- 관성 계산은 기존 rAF/ref 루프에서 수행하고 React 상태를 매 프레임 갱신하지 않습니다. 포인터 기록과 스파클/흔적 DOM 풀의 크기는 제한됩니다. 배경의 추가 광원과 별은 정적 CSS입니다.
- 기존 충돌은 여유 간격이 있는 사각 경계 근사이며, 캡슐 쌍 전체를 비교하므로 키워드가 매우 많으면 O(n²) 비용과 합성 레이어 메모리 비용이 증가합니다.
- 놓은 위치가 점유됐거나 경계 밖이면 빈자리 보정이나 충돌 때문에 관성이 짧아지거나 방향이 바뀔 수 있습니다.
- 관성 이동은 입력 속도와 방향, 충돌, 동작 감소 설정에 따라 달라집니다. 위 이동 거리는 해당 검증 제스처의 실측값입니다.
- 매우 긴 프레임 간격을 제한하는 기존 구조 때문에 심한 렌더링 지연 환경에서는 시뮬레이션 시간이 느려질 수 있습니다.
- 실제 RTX 3050 Ti FPS와 실기기 iPhone/iPad Safari는 측정하지 않았습니다. 에뮬레이션 결과를 실기기 성능 검증으로 해석하지 않습니다.
- 실제 AI 응답과 오로라 결과 화면은 이번 단계에서 실행 검증하지 않았습니다. 해당 코드가 변경되지 않았음을 확인했습니다.
