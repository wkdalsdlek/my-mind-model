# 캡슐 반발·스파클·드래그·시간대 배경 검증

검증일: 2026-10-12. Chromium 156.0.8078.4, CPU 렌더러로 실제 페이지를 실행했습니다. 이 문서는 앞선 자유 부유 검증 이후 추가 변경을 기록합니다.

## 변경 범위

- 질문 화면의 캡슐 글자 크기를 약 11% 확대했습니다. 데스크톱 원본은 13 → 14.4px, 선택 캡슐과 모바일 원본은 12 → 13.3px입니다. 긴 단어는 기존 줄바꿈을 유지하고 변경된 실제 크기로 충돌 경계를 측정합니다.
- 캡슐 충돌의 상대 속도 반발 계수를 0.18 → 0.42로 높였습니다. 유의미한 접근에는 최소 2.4px/s의 상대 분리 속도를 주고, 0.5초 동안 조향을 약하게 해 반발을 즉시 상쇄하지 않습니다.
- 경계는 22px 전부터 조향하고, 경계 가까이에서 접근 속도의 46%를 남겨 안쪽으로 튕깁니다. 반발 후 약 0.55초 동안 조향을 완화합니다. 기존 느린 이동, 15px/s 속도 제한과 12px의 안전 간격은 유지합니다.
- 충돌/경계 사건을 효과 레이어에 전달합니다. 스파클은 최대 6개 DOM 노드를 재사용하며 1회 3개, 360ms 동안 표시합니다. 전체 300ms, 같은 캡슐 쌍 또는 경계 사건 850ms의 쿨다운을 둡니다. 동작 감소 환경에서는 2개, 220ms로 줄입니다.
- 드래그는 복제 고스트 대신 원본 DOM을 브라우저의 수동 Popover 최상위 레이어에 표시합니다. 원래 그리드에는 크기를 보존하는 자리표시자를 둡니다. Popover를 지원하지 않으면 같은 원본을 body로 옮겼다가 복원합니다.
- 드래그한 몸체는 포인터 위치와 함께 이동하되 자체 적분과 위치 보정은 중지합니다. 공간 밖에서는 다른 몸체의 충돌 비교에서도 제외합니다. 일반 이동은 React 상태 대신 ref와 transform으로 처리합니다.
- 답변칸 밖에서 놓으면 놓은 중심에서 재개합니다. 경계 밖이면 가까운 공간 경계로 제한하고, 점유된 위치라면 놓은 점에 가까운 빈자리를 찾습니다. 성공 드롭은 답변을 추가하고 재사용할 원본을 출발 지점 가까이 유지합니다. 취소·Escape는 출발 지점으로 복원합니다.
- 드래그 흔적은 최대 8개 DOM 노드를 재사용하며 330ms 동안 사라집니다. 40ms 간격과 최소 이동 거리 7px를 적용하고, 캡슐 뒤쪽 가장자리에서 방출해 느린 이동에서도 유리에 완전히 가려지지 않도록 합니다.
- 배경은 질문 컴포넌트 밖의 유지되는 레이어에서 아침/점심/저녁/밤의 opacity를 1250ms에 걸쳐 전환합니다. 동작 감소 환경은 600ms입니다. 3번과 6번 질문에서는 인접 시간대 레이어를 혼합합니다.

## 실제 브라우저 측정

### 반발과 스파클

- 자연 부유 좌표를 35초 동안 690회 측정했습니다.
- 자연/창작 캡슐의 y 방향 간격은 접근 전 14.670px → 접촉 시 12.020px → 약 815ms 후 15.428px로 증가했습니다. 실제 화면 좌표에서 접근 후 반발을 확인했습니다.
- 캡슐 충돌 및 경계 접촉 스파클을 모두 관찰했습니다. 35초 동안 39회 방출했고, 동시 실행 입자는 최대 6개였습니다. 관측한 최소 방출 간격은 300.6ms입니다.
- 별도의 25초 관측에서는 249회 실제 좌표를 측정했으며 겹침·영역 이탈은 0건이었습니다.
- 800×640, 350×650, 304×650 공간에서 각각 120초 계산 테스트도 통과했습니다. 실제 좌표 측정과 별개의 보조 검증입니다.

### 드래그와 기존 기능

- 원본 캡슐의 DOM 동일성과 Popover 표시 상태를 확인했습니다. 포인터 목표와 원본 중심이 일치했습니다.
- 원본 중심 (722.109, 198.250)을 (823.875, 246.000)에 드래그해 놓았을 때, 실제 중심은 (823.875, 246.000)이었습니다. 원위치로 돌아가지 않았고 이후 부유가 재개됐습니다.
- 포인터를 누르고 있는 600ms 동안 해당 몸체가 정지했습니다. 답변칸 활성 표시, 성공 드롭 1회 추가, 재사용 원본 유지 및 성공 드롭 후 부유 재개를 확인했습니다.
- 중복 선택, 삭제, Escape 취소, 질문 이동 후 선택 상태 유지를 확인했습니다. 긴 새 키워드 생성도 모바일/iPad에서 확인했습니다.
- Popover API를 비활성화한 Chromium에서 body 이동 대체 경로와 복원 후 겹침·경계 이탈 없음도 확인했습니다.
- iPad 에뮬레이션에 DevTools 프로토콜의 실제 touchStart/Move/End를 보내 원본 터치 드래그, 의도하지 않은 답변 추가 없음, 드롭 후 느린 부유 재개를 확인했습니다.
- 느린 마우스 드래그에서도 화면 좌표와 opacity를 측정해 유리 밖에 표시되는 흔적을 확인했습니다. 입자 DOM만 생성됐는지 확인한 것이 아닙니다.

### 배경과 반응형 화면

| 질문 | 배경 |
| --- | --- |
| 1–2 | 아침: 블루·라벤더·피치 |
| 3 | 아침 → 점심 혼합 |
| 4–5 | 점심: 청록·하늘빛·실버 |
| 6 | 점심 → 저녁 혼합 |
| 7–8 | 저녁: 로즈·보라·골드 |
| 9–10 | 밤: 딥 네이비·인디고·오로라빛 |

- 전체 순서가 위 표와 일치했습니다. 질문 전환 전후 배경 DOM이 동일하게 유지됐습니다.
- 2 → 3번 전환에서 아침 레이어 opacity가 1 → 0.927 → 0.550으로 바뀌어 전환 중간값을 실제로 관측했습니다.
- 모바일 390px/iPad 810px는 동작 감소 환경에서 각각 10초, 100회 측정했고 모바일 320px는 6초, 60회 측정했습니다. 16자 키워드를 포함해 겹침·공간 이탈·가로 넘침은 0건이었습니다.
- 터치 탭으로 중복 선택·삭제가 작동했습니다. 긴 단어는 줄바꿈됩니다. 세로로 넘치는 부유 공간은 기존처럼 스크롤합니다.
- 아침/점심/저녁/밤 및 모바일/iPad 스크린샷을 캡처했고 데스크톱 아침/저녁과 작은 모바일 화면을 시각 확인했습니다.

## 남은 한계

- 충돌은 둥근 캡슐의 정밀 접촉이 아니라 여유 간격을 포함한 사각 경계 근사입니다. 정확히 유리 표면에 닿기 전 반발할 수 있습니다.
- 놓은 위치가 다른 캡슐로 점유됐거나 경계 밖이면 가까운 빈 위치로 보정합니다. 공간이 매우 붐비면 이동 폭이 커질 수 있습니다.
- 키워드를 매우 많이 생성하면 전체 쌍 비교의 O(n²) 비용과 캡슐 합성 레이어 비용이 증가합니다. 스파클과 흔적은 고정 풀을 사용합니다. 새 물리·3D 라이브러리는 추가하지 않았습니다.
- 실제 RTX 3050 Ti의 FPS, 실기기 iPhone/iPad 및 Safari는 검증하지 않았습니다. Chromium 에뮬레이션 결과를 해당 기기의 성능이나 호환성 검증으로 해석하지 않습니다.
- 실제 AI 분석 응답과 오로라 결과 화면의 런타임은 이번 단계에서 재검증하지 않았습니다. 해당 코드를 수정하지 않았음을 확인했습니다.
