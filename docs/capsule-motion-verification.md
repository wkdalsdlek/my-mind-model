# 캡슐 부유 및 유리 질감 검증

검증일: 2026-10-12. 브라우저: Chromium 156.0.8078.4 (headless).

## 확인한 정지 원인

사용자 Chrome에서 `prefers-reduced-motion: reduce`가 `true`임을 확인했습니다. 기존 미디어 규칙은 `.floatingCapsule`에 `animation: none`을 적용했습니다. 인라인 재생 상태가 `running`이어도 계산된 애니메이션 이름은 `none`, 지속 시간은 `0s`, 실제 애니메이션 수는 0이었습니다.

Chromium에서 같은 조건을 재현했고, 수정 전 12개 캡슐 모두 10초 동안 x/y 좌표 변화가 0이었습니다. 일반 설정에서는 기존 keyframes가 적용되고 실제 이동도 관측되었습니다. 부유 래퍼와 드래그 포털은 별도 요소이므로 transform 충돌은 확인되지 않았습니다.

## 수정

- 요청된 부유는 동작 감소 환경에서도 이동 범위 60%, 주기 125%로 실행합니다. 기존 드롭 전환의 동작 감소 처리는 유지합니다.
- 부유 멈춤 버튼으로 완전히 정지할 수 있습니다. 선택은 세션 안에서 질문을 이동해도 유지됩니다.
- ID별 위상·방향·주기를 다르게 하고 의미 그룹별 이동 성격을 유지합니다. 이동은 각 슬롯의 여백 안에 제한합니다.
- 부유 중 회전·축소를 제거해 텍스트 선명도를 유지합니다. 드래그는 기존 독립 포털에서 처리합니다.
- CSS 반사층, 안쪽 굴절선, 측면 곡률, 하단 내부 그림자와 색 안개로 두께를 표현합니다. WebGL이나 새 런타임 의존성은 추가하지 않았습니다.

`getBoundingClientRect()`로 캡슐 중심을 측정했습니다. 각 설정에서 2.5초 간격으로 5회 측정했으며 실제 경과 시간을 기록했습니다.

## 추가 확인

- 일반·동작 감소 설정 모두에서 드래그 중 좌표가 고정되었고, 성공한 드롭 및 실패한 드롭 뒤 5초 동안 3회 좌표 측정으로 재개를 확인했습니다.
- 수동 정지 시 CSS Animation의 pending 상태가 해제된 뒤 실제 타임라인이 고정되는 것을 확인했습니다. 자동 스크롤에 따른 화면 좌표 변화와 부유를 구분했습니다.
- 중복 선택, 동일 단어 생성, 삭제, 질문 이동 후 복원, 키보드 선택을 확인했습니다.
- mobile 터치 에뮬레이션: 폭 320, 390px에서 탭·중복·삭제 및 긴 키워드를 포함한 13개 캡슐의 겹침과 슬롯 경계를 반복 확인했습니다.
- ipad 터치 에뮬레이션: 폭 810px에서 탭·중복·삭제 및 긴 키워드를 포함한 13개 캡슐의 겹침과 슬롯 경계를 반복 확인했습니다.
- 세로로 넘치는 캡슐은 기존 키워드 공간의 스크롤로 접근합니다. 스크롤 위치와 무관하게 각 캡슐이 자기 슬롯 및 공간의 가로 경계 안에 있는지 검사했습니다.
- 브라우저 런타임 오류: 0건.
- `npx tsc --noEmit`: 통과.
- `npm run lint`: 통과.

## 검증 범위의 한계

- 모바일·iPad는 Chromium의 터치/뷰포트 에뮬레이션입니다. 실제 iPhone·iPad Safari 및 RTX 3050 Ti 하드웨어 성능은 측정하지 않았습니다.
- 실제 OpenAI 분석 호출은 실행하지 않았습니다. AI API, 결과 화면 및 질문 데이터 파일의 수정 전후 해시가 동일함을 확인했습니다.
- 유리 질감은 CSS 시각 표현이며 실제 광학 굴절 시뮬레이션은 아닙니다.
