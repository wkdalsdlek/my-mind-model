# Cinematic Orbit Viewer · 구현 및 검증

작업일: 2026-10-14. 브랜치: `feat/glass-nebula-aurora`.

후속 [360도 시각 품질 개선](./aurora-orbit-quality-verification.md)에서 리본/안개 예산과 안전 외곽을 보강하고 유리 조각을 중심 주변으로 재배치했습니다. 아래 거리·정점·테스트 수치는 카메라 구현 당시 기록이며 최신 수치는 후속 문서를 따릅니다. 세 카메라 모드와 조작 정책은 유지합니다.

이번 작업은 기존 미커밋 Glass Nebula Aurora 구현을 이어서 `/aurora-lab`에만 적용했습니다. 질문·캡슐 물리·하늘·Q10 추천/문장 생성/승인·분석 API·기존 결과 화면을 수정하지 않았습니다. 커밋·푸시·배포·브랜치 전환·환경변수 변경·리뷰 ZIP 변경도 하지 않았습니다.

## 1. 세 가지 카메라 모드

- **Front View**: 초기 기본값. 자동 회전 없이 오로라 자체의 기존 파동/중심장/루프 운동을 감상합니다. 정면에서는 카메라 입력을 끕니다.
- **Free Orbit**: 마우스 왼쪽 드래그 또는 한 손가락 드래그로 중심을 둘러봅니다. 휠/두 손가락 핀치로 거리를 조절합니다.
- **Cinematic Auto Orbit**: 현재 방향에서 느린 수평 공전을 시작합니다. 접을 수 있는 카메라 섹션에 선택기·정면 복귀·상태·조작 안내를 추가했습니다. 기존 프리셋·품질·흐름·리본 수·레이어 옵션은 유지합니다.

## 2. 자동 공전의 속도와 경로

기본 한 바퀴는 **120초**, 변경 가능한 범위는 90~150초입니다. `GlassNebulaAurora`의 선택적 `cameraOptions={{ autoOrbitSeconds: 120, returnSeconds: 1.2 }}` 또는 `lib/aurora-camera.ts` 기본값으로 조절할 수 있습니다. 초기 가속을 지수 곡선으로 적분하며 30/60/120FPS의 동일 경과 시간에 같은 각도를 얻는지 검사했습니다. 첫 한 바퀴는 가속 시간 때문에 정속 120초보다 조금 길어집니다.

초점은 실제 리본/루프/미스트 깊이를 반영한 `[0, 0.15, -2.4]`입니다. 공전 중 높이와 거리는 수평 안전 경로로 완만하게 수렴합니다. 정면을 지날 때 각도를 초기화하거나 멈추지 않습니다. 탭 복귀의 긴 delta는 0.25초로 제한해 점프를 줄입니다. 매우 낮은 FPS에서는 실제 벽시계 공전 시간이 길어질 수 있습니다.

## 3. 자유 탐색의 제한과 프레이밍

수평 방위각은 무제한, 수직은 수평 기준 약 ±60°입니다. 패닝은 끄고 회전 감도 0.38, 줌 감도 0.65를 사용합니다. 일반 환경에는 감속 관성이 있고 움직임 감소에서는 관성을 끕니다.

최소 거리는 15.5로 주요 구조의 안전 외곽보다 큽니다. 최대 거리는 화면 비율/리본 수에 따라 산출한 자동 공전 거리의 약 1.67배입니다. 기본 리본 3개에서 800×600은 정면 거리 25.32·최대 44.01, 390×844는 정면 48.80·최대 93.14입니다. 세로 화면에서는 FOV와 거리만 바꿔 핵심 구조를 담습니다. 수동으로 최소 거리까지 확대하면 화면 일부가 잘릴 수 있습니다.

정적 안전 외곽을 리본 수별로 선택하고 모서리 투영/48개 수평 시점으로 프레이밍을 계산합니다. 프레임별 동적 바운딩 계산은 하지 않습니다. 모든 프리셋·루프/미스트·비교 강도의 실제 곡면과 CPU pose 표본을 안전 영역과 대조했으며 GPU 정점 파동을 위한 여유를 둡니다. 이는 가능한 모든 변형을 수학적으로 증명한 경계는 아닙니다.

## 4. 자동 감상 중 직접 조작

캔버스 입력 시작 즉시 자동 공전을 중단하고 현재 위치에서 Free Orbit으로 전환합니다. 드래그가 끝나도 자동으로 재개하지 않습니다. 자동 모드를 명시적으로 다시 선택하면 현재 방향에서 새 가속으로 이어갑니다. OrbitControls는 캔버스에만 연결하므로 패널 조작이 카메라에 전달되지 않습니다.

시스템 또는 패널의 움직임 감소가 켜지면 자동 선택을 비활성화하고 정면으로 부드럽게 돌아갑니다. 감소 설정 해제만으로 자동 감상을 재시작하지 않습니다. 감소 상태에서도 수동 탐색은 가능합니다.

## 5. 정면 복귀와 카메라 소유권

기본 **1.2초**(설정 범위 0.8~1.5초)의 cubic ease-out을 사용합니다. 현재 구면 좌표에서 가장 짧은 방위각 경로로 복귀하므로 장면 내부를 직선으로 가로지르지 않습니다. 카메라 모드·리본 수·화면 비율 변경은 오로라 클록/위상을 재생성하지 않습니다.

`AuroraCameraController` 한 곳에서 카메라를 소유합니다. 수동 프레임에는 OrbitControls, 자동/복귀 프레임에는 구면 좌표 업데이트를 실행합니다. 기존 Drei 제어기와 장면 전체의 포인터 기울기는 제거했습니다. 매 프레임 React state나 카메라 벡터를 생성하지 않습니다. 명시적 모드 변경은 기존 관성을 정리하고, 직접 조작으로 자동을 멈출 때는 활성 포인터 제어기를 보존합니다. Strict Mode 재실행/언마운트에는 이벤트를 포함한 controls를 dispose합니다.

## 6. 측면·후면 그래픽 보정

- 리본·루프·미스트의 기존 양면 렌더링·닫힌 연결부·깊이/공전/색/발광 셰이더를 재사용합니다. 카메라로 리본 자체 운동을 대체하지 않습니다.
- 앞쪽 전용 성운 면은 모든 시점에서 필드 뒤를 향하는 부드러운 배경층으로 배치합니다. 기존 노이즈·깊이 간격·팔레트·기울기를 유지하면서 측면의 평면 노출/후면 소멸을 줄입니다. 실제 볼륨 광산란은 아닙니다.
- 먼 별은 기존 결정적 버퍼에서 중심을 둘러싼 구형 분포로 GPU 배치해 후면의 빈 별 배경을 보정합니다. 가까운 먼지와 입자 수는 유지합니다. 정면의 개별 별 위치는 이전과 달라집니다.
- 유리 인스턴스의 실제 bounding sphere를 계산하고 리본과 같은 renderOrder에서 중심 깊이로 정렬해 후면에서도 고정 전경으로 그려지는 문제를 줄입니다. Fresnel의 pow 입력도 안전 범위로 제한합니다.
- 기존 Bloom과 리본 유색 코어를 바꾸지 않아 추가 순백색 발광을 만들지 않습니다. 소프트웨어 저화질 측면에서는 접힌 면/자기 교차가 각진 투명 면처럼 보이는 부분이 남습니다. 인스턴스별/삼각형별 완전한 투명 정렬이나 OIT는 구현하지 않았습니다.

## 7. High Fidelity First

화면이 작다는 이유로 입자·리본 해상도·루프·미스트·DPR·Bloom 예산을 자동 축소하던 분기를 없앴습니다. 기존 low/balanced/high 선택을 모든 기기에서 동일하게 적용하며 기본값은 balanced입니다. `auroraQualityBudget`의 기존 두 번째 인수는 호출 호환성만 유지합니다. 시스템 움직임 감소와 비활성 탭 정책은 품질 설정과 별개입니다.

이번에는 GPU 기반 자동 품질 변경을 추가하지 않았습니다. FPS 진단은 유지하고 느린 유효 프레임도 표본에 포함합니다. 60FPS·모바일 발열/배터리/메모리는 보장하거나 검증하지 않았습니다. 브라우저 검사는 소프트웨어 렌더링 부담을 줄이기 위해 검사 도중 **명시적으로 low를 선택**했으며 모바일의 자동 저화질 전환이 아닙니다.

## 10. 남은 실제 기기 확인

실제 Chrome/Safari·모바일 터치와 GPU에서 balanced/high의 측면/후면을 확인해야 합니다. 루프 접선 방향에서 얇아지는 실루엣, 저화질의 각진 접힘, 교차 투명도/유리 인스턴스 정렬, 안개가 카메라를 따르는 근사 표현을 추가 평가해야 합니다. 정면에서 색감/밝기가 유지되는지와 네 프리셋/모드/품질 전환의 미학적 만족도도 실제 화면에서 판단해야 합니다.

소프트웨어 WebGL 실행은 하드웨어 FPS·GPU 메모리·누수·장시간 발열/배터리 검증이 아닙니다. 반복 전환/경로 이탈 후 GPU 자원 수치와 장시간 120초 궤도는 실기기에서 측정해야 합니다. 자동 수학 검사에서는 정속/클록/전환을 확인했지만 브라우저에서 실제 벽시계 120초 한 바퀴를 재지는 않았습니다. 이번 단계는 독립 실험실에서 종료하며 기존 결과 화면에 연결하지 않습니다.
