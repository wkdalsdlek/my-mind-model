# Q10 Preview 입력 예산 검증

## 확인된 실제 원인

- 기준 커밋: `01ebe4b4c65365c4a92902b26c77e471bc0e02cb`.
- 기존 Beta Preview의 서버 진단 로그 2건 모두 `feature: closing`, `mismatchTypes: [INPUT_BYTES_EXCEEDED]`였다.
- `Buffer.byteLength(JSON.stringify(params), "utf8") + 4096`은 16,140바이트, 유효 상한은 16,000이었다. 140바이트 초과로 SDK 실행 전에 차단됐다.
- 모델명 불일치 진단은 없었다. 실제 라우트의 `gpt-4o-mini`와 `featureModel("closing")`이 일치하고, 요청·예산의 최대 출력은 모두 180이었다.
- 로그는 기존 Preview 전용 allowlist 진단에서 고정 식별값과 숫자만 추출했다. 답변, 승인 문장, 프롬프트, 키, 세션, 가격표 Secret은 출력하지 않았다.

## 최소 변경

`featureBudgetConfig`에서 Preview의 `closing` 기능만 `AI_CLOSING_MAX_INPUT_BYTES`를 읽는다. 오로라 해석은 기존 `AI_INTERPRETATION_MAX_INPUT_BYTES`를 계속 사용한다. 레거시 `analyze` 및 Preview 외 환경에는 두 설정을 적용하지 않는다.

- 누락: 기존 가격표의 한도 유지. 기본 예산 설정이 없으면 여전히 거부한다.
- 명시적 설정: 정규 정수 문자열, 4,096~120,000만 허용한다. 빈 문자열, 공백, 소수, 지수 표기, 범위 초과는 예약 전에 `BUDGET_NOT_CONFIGURED`로 거부한다.
- 요청별 가격표 복사본에서 해당 모델의 `maxInputTokens`만 변경한다. 실제 단가·Secret·공통 예산·계정 설정은 변경하지 않는다.
- 120,000바이트에는 4,096바이트의 기존 오버헤드가 포함된다. SDK 파라미터 JSON 자체의 한도는 115,904바이트다. 관측된 요청에는 103,860바이트의 여유가 생긴다. 모든 극단적인 허용 입력이 무조건 통과한다고 보장하지 않는다.

`reserveUsage`가 같은 요청별 설정을 `ModelPermit`에 전달하므로 다음 세 지점의 유효 상한은 모두 동일하다. `usage.ts`를 변경하거나 검증을 우회하지 않는다.

1. 모델 호출 전 최대 비용 예약 및 DB의 `price_snapshot`.
2. 실제 SDK 요청 UTF-8 바이트 + 4,096 검사.
3. OpenAI 보고 입력 토큰 상한 검사와 실제 비용 정산.

Q10의 모델, 프롬프트, strict JSON 스키마, 180토큰 출력, 최대 1회 호출을 유지한다. 해석 모델·추론 수준·최대 2회 정책, Q10 승인, 인증, 3D 및 UI는 변경하지 않는다.

## 비용과 실패 정책

예약액은 기존 공식 `ceil(cost(price, effectiveInputBound, outputBound) * attempts * 1e8) / 1e8`이다. 테스트용 참고 단가(입력 $0.15 / 출력 $0.60, 각각 백만 토큰당)에서는 Q10 120,000 입력 + 180 출력 × 1회의 최대 예약액이 **$0.018108**이다. 기존 16,000 한도의 $0.002508보다 커지지만 실제 과금 추정치는 보고된 토큰으로 정산한다. 운영 가격표 Secret을 읽거나 변경하지 않았으므로 운영 예약액은 기존 Secret의 단가에 따른다.

- 사용자·계정·전역의 남은 예산이 예약액보다 적으면 기존 HTTP 429로 차단한다. 예산을 자동으로 늘리지 않는다.
- 모델 미호출 시 0으로 정산한다. 정상 사용량이면 실제 추정 비용으로 정산한다.
- 공급자 실패, 사용량 누락, 상한을 넘는 보고 사용량은 불확실 상태로 기존 최대 예약액을 유지한다.
- 한 번 실행된 Q10 permit으로 두 번째 호출은 허용하지 않는다. 예약 후 환경 설정이 바뀌어도 해당 요청의 상한은 고정한다.

## 검증

새 단위 테스트는 관측된 16,140바이트 실패, Preview 격리, 잘못된 설정, 기능 간 독립성, 16/60/90/110/120KB 및 120,001바이트 경계, 모델·출력 불일치 구분, 비용 예약·정산, 사용량 이상, 취소, 계정·예산 차단을 검사한다.

실제 `app/api/closing-message/route.ts`를 모의 OpenAI SDK와 연결한 테스트는 동일한 합성 Q1~Q10 입력으로 기존 한도에서 실패하고 Q10 설정 적용 후 성공하는지 확인한다. SDK 요청의 모델·프롬프트·스키마가 전후 동일함을 비교한다. 실제 OpenAI 통신은 하지 않는다.

독립 로컬 PostgreSQL 컨테이너에서 기존 보안 테스트와 Q10 상한의 예약/정산·단일 호출·예산 차단·해석 한도 보존 테스트를 실행한다. 운영 DB를 사용하지 않으며 테스트 컨테이너는 제거한다.

최종 검사 결과:

- 작업 트리: TypeScript, ESLint 통과. 비DB 628개 + 독립 PostgreSQL 52개 = 680개 통과, 실패·skip 0.
- 기존 인증 진단 미커밋 파일을 제외한 깨끗한 배포 후보: TypeScript, ESLint 통과. 비DB 612개 + 독립 PostgreSQL 52개 = 664개 통과, 실패·skip 0.
- 차이 16개는 보존한 미추적 인증 진단 테스트다. 배포 후보에는 이 별도 작업을 포함하지 않았다.
- 신규 Q10 단위 테스트 37개와 DB 테스트 2개가 추가됐다. 기존 해석 입력 예산, 인증·권한, 취소·시간 제한 테스트도 통과했다.
- `git diff --check` 및 커밋 대상 자격증명 패턴 검사 통과. 스테이징 검토는 커밋 직전에 다시 수행한다.

## Preview 반영 절차 및 미검증 범위

1. 승인된 변경 파일만 커밋·일반 푸시한다. 기존 미커밋 인증 진단 및 ZIP은 보존한다.
2. 기존 `wkdalsdleks-projects/my-mind-model-beta`의 연결·현재 alias·소스 커밋을 확인한다.
3. Preview에 `AI_CLOSING_MAX_INPUT_BYTES=120000`만 추가한다. 해석 설정 120,000 및 다른 환경변수·Secret 메타데이터가 그대로인지 확인한다.
4. 새 커밋만 `git archive`로 추출한 소스를 Preview에 배포한다. READY·프로젝트·소스 커밋을 확인한 후 기존 고정 Preview alias를 연결한다. Production 배포 포인터가 그대로인지 확인한다.

실제 유료 모델 호출과 사용자의 브라우저 생성 성공은 검증하지 않는다. READY와 모의 성공은 실제 모델 접근 권한·품질·지연·실사용 과금을 검증한 결과가 아니다. 이후 사용자 테스트에서 다른 오류가 발생하면 기존 Preview의 안전한 진단 코드로 구분한다.
