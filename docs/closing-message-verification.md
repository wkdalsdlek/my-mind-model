## API와 모델

- `POST /api/closing-message`: `{ requestId, input, previousText? }` → `{ requestId, text }`.
- 입력은 Q10 실제 선택의 `keywordId / selectionId / questionId / label / originalText / source / answerIntent`, 미제출 원문 `authoredText`·단어 `authoredWord`, Q1~Q9의 응답 상태 및 실제 선택만입니다. 추천 후보 14개와 의미 가중치·추천 전체 근거는 보내지 않습니다.
- 문장 입력은 기존 1000자, 단어는 16자를 유지합니다. 본문은 선언된 길이와 실제 스트림 모두 128 KiB까지, 질문당 선택 100개, 전체 300개, 라벨·원문 합계 24000자까지 제한합니다. 원문은 줄바꿈·앞뒤 공백까지 보존합니다.
- 질문 ID·선택 ID·데이터 타입·배열·응답 상태·중복 ID를 검증합니다. Q3·Q7·Q8·Q9의 의도는 서버 정의와 일치해야 합니다. 건너뛰기는 선택된 표현이나 추론한 감정으로 취급하지 않습니다.
- 기존 OpenAI SDK의 Chat Completions와 `gpt-4o-mini`, 서버 전용 `OPENAI_API_KEY`를 사용합니다. SDK 재시도는 0회, 타임아웃은 30초, 요청당 출력 토큰 상한은 180이며 SDK 로깅을 끕니다. 클라이언트 요청에는 키가 없고 응답에도 키·SDK 내부 오류·입력 원문을 반사하지 않습니다.
- JSON Schema의 엄격한 `{ text: string }` 출력을 요청합니다. 서버에서 JSON 형식·필드 수·공백·빈 문자열·한국어 포함·최대 80자·줄바꿈·마크다운·설명 접두사를 재검증합니다. 목표는 공백 포함 20~45자이며, 출력의 20자 하한을 강제하지 않습니다. 거절·토큰 소진·잘못된 응답은 오류로 처리합니다.
- 프롬프트는 직접 표현의 의미와 부정적 감정을 존중하고 진단·성격 단정·질환 추정·미래 예언·무의식 해석을 금지합니다. 입력 속 지시문은 시스템 메시지에 붙이지 않고 별도의 user JSON 데이터로 전달합니다. 재생성 시 이전 AI 문장은 변형 참고값이며 의미의 근거가 아닙니다.
- 키 누락은 503, 잘못된 입력은 400/415, 과도한 요청 크기는 413, 생성·응답 오류는 502, 제한 초과는 429, 취소는 408입니다. 클라이언트에는 정해진 오류 코드와 한국어 안내만 표시하며 가짜 성공 문장은 반환하지 않습니다.

설계 시 확인한 [공식 OpenAI Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat). 설치된 SDK 타입과 README에서 타임아웃·재시도·요청 signal 계약을 확인했습니다.

## 원문·수정·승인 계약

- `QuestionnaireState.personalization.recommendations`: 기존 추천 후보 14개.
- `QuestionnaireState.selections[9]`: 실제 선택·반복 선택·개별 선택 ID, 선택된 사용자 원문.
- `QuestionnaireState.closing.authoredText / authoredWord`: 아직 제출하지 않은 직접 작성 원문. AI 생성이나 직접 승인으로 지우지 않습니다. 사용자가 답변·필드에 명시적으로 제출하는 기존 동작은 해당 필드만 비웁니다.
- `closing.aiDraft`: AI 초안의 `text`·`inputFingerprint`.
- `closing.editedDraft`: 직접 수정/작성한 원문, 입력 스냅샷, `user-edited / user-authored` 출처. AI 원본과 별도로 보존합니다.
- `closing.approved`: `{ text, source: 'ai' | 'user-edited' | 'user-authored', approvedAt, inputFingerprint }`. 승인 시에만 설정하며 AI가 자동으로 승인하지 않습니다. 최종값의 앞뒤 공백은 정리하되 작성 원문에는 적용하지 않습니다.
- `closing.request`: 요청 ID와 입력 스냅샷. `closing.error / notice`는 진행 실패·무효화 안내입니다.
- 사용자 승인 문장은 한 글자도 허용하며 공백만 있는 값과 1000자 초과만 제한합니다. 진단이나 의미 판단으로 사용자 원문 승인을 차단하지 않습니다. 자동 생성 문장의 형식 제한은 별도입니다.
- 2단계의 예약 `personalization.condensedSentence / approvedSentence`는 호환을 위해 그대로 남지만 활성 승인값으로 사용하지 않습니다.

## 무효화·중복·지연 응답

- Q1~Q9 및 Q10의 실제 선택·삭제·건너뛰기 변경과 Q10 미제출 단어·문장 변경은 같은 reducer에서 승인·진행 요청을 해제합니다. 기존 2단계 추천 무효화와 추천에서 고른 Q10 선택 삭제도 그대로 수행합니다. 원문·직접 선택은 보존합니다.
- AI 재생성을 시작하거나 최종 문장을 직접 수정해도 이전 승인을 해제합니다. 직접 수정/작성 초안은 최대 1000자이며 수정할 때마다 현재 입력 스냅샷을 붙입니다.
- 이전 AI·수정 초안은 남겨 보여 주되 이전 입력의 초안임을 표시하고 그대로 재승인할 수 없습니다. 새로 생성하거나 사용자가 **직접 수정**으로 현재 입력에서 다시 받아들여야 합니다. 삭제 없는 작업이나 같은 원문 값은 입력 무효화를 일으키지 않습니다.
- `inputFingerprint`는 원문·각 선택 ID·반복 선택·응답 상태를 포함한 손실 없는 JSON 스냅샷입니다. 승인 조회 함수도 현재 스냅샷을 검사합니다. 이 값에는 사용자 원문이 포함될 수 있으므로 익명 해시나 공개 로그 식별자로 취급하지 않습니다. 현재는 React 메모리에만 있습니다.
- 클라이언트 controller는 React 렌더링 이전에 동기 잠금을 설정합니다. 입력 변경·이전 질문 이동·재시작·컴포넌트 해제 시 AbortController로 취소합니다. 클라이언트 대기 상한은 35초입니다.
- fetch가 취소를 무시하더라도 현재 요청 객체가 아닌 결과를 전달하지 않습니다. 응답의 `requestId`도 확인합니다. reducer에서 요청 ID와 현재 입력 스냅샷을 다시 검사하므로 이전 입력으로 되돌아가더라도 취소한 요청은 살아나지 않습니다.
- 취소는 오래된 결과 반영을 막지만, 이미 실행된 외부 모델 요청의 비용까지 되돌린다고 보장하지 않습니다.

## 배포 전 보안·남용 방지 위험 및 한계

- 기존 입장 비밀번호는 클라이언트 조건문이며 새 API의 서버 인증을 보장하지 않습니다. 서버 인증을 전면 교체하지 않았으므로 API를 직접 호출할 수 있습니다.
- 동일 Origin 및 cross-site 검사, JSON 전용 입력, 요청 크기·출력 토큰 상한, HTTP-only SameSite=Strict 쿠키 기반 세션 제한을 추가했습니다. X-Forwarded-For를 신뢰하는 IP 인증은 사용하지 않습니다.
