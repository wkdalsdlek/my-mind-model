# Glass Nebula Aurora 1단계 검증

검증일: 2026-10-13. 범위는 확정 질문·데이터 계약·기존 캡슐 UX 연결입니다.

## 구현

- Q1~Q9의 질문 및 126개 키워드를 전달받은 한국어 원문 그대로 통합했습니다. 키워드 ID는 `q1-01`~`q9-14`로 명시하여 배열 순서를 바꾸어도 식별자가 바뀌지 않습니다.
- 일곱 의미 계열의 ID·이름·색·정의를 별도 모듈로 관리합니다. 기존 `calm / warm / depth / energy`와 물리 속도·색상은 유지합니다.
- 126개 초기 매핑은 키워드 ID별 주요·보조 의미와 가중치 배열입니다. 일반 0.7/0.3, 단일 1.0 및 제공된 0.8/0.2, 0.6/0.4, 0.65/0.35 예외를 반영했습니다.
- 질문별 `answerIntent`와 시각 역할을 명시했습니다. 핵심 기여 설정에는 Q1 .18, Q2 .13, Q4 .20, Q5 .20, Q6 .29만 포함합니다. 실제 집계·렌더링은 후속 단계입니다.
- `SelectedCapsule[][]`, 원본 키워드 ID, 개별 선택 ID와 중복 선택을 유지합니다. 질문 ID·입력 원문·출처·의미 가중치·답변 맥락을 확장하고, 선택 시 가중치를 복사하여 독립된 스냅샷으로 보존합니다.
- 응답 상태는 `pending / answered / skipped`로 구분합니다. Q1~Q9의 빈 응답만 명시적으로 건너뛸 수 있으며, 다시 선택하면 `answered`, 마지막 선택을 삭제하면 `pending`입니다. Q10 건너뛰기는 허용하지 않습니다.
- `serializeSelections`는 유지합니다. 호환 어댑터는 명시적인 건너뛰기만 `[사용자가 건너뛴 문항 — 선택한 키워드 없음]`으로 전달합니다. 기존 API의 `{ answers, questions }` 계약과 프롬프트는 유지했습니다.
- Q10은 확정 질문·보조 문구·개인화 타입 계약만 준비했습니다. 고정·임의 추천 키워드는 없습니다. 직접 입력은 최대 200자까지 기존 생성·선택 UX로 처리합니다. AI 추천·함축·승인은 구현하지 않았습니다.
- 긴 캡슐 때문에 모바일 104px 고정 행을 넘는 경우를 대비해 행 높이를 내용에 맞게 확장합니다. 데스크톱도 자동 행 높이를 사용하며, 38:62/모바일 세로 레이아웃과 측정 기반 드래그 판정을 유지합니다.
- 선택·삭제·건너뛰기는 키워드 풀 배열을 교체하지 않습니다. 물리 훅의 키워드 의존성 및 기존 질문별 마운트 정책은 유지합니다. 실제 키워드 추가·질문 전환에 필요한 재측정은 기존대로 수행합니다.

## 실제 브라우저 회귀: 미검증

현재 환경에는 Chrome/Chromium 실행 파일과 브라우저 자동화 도구가 없어 다음 항목은 실제 브라우저에서 확인하지 못했습니다. 이전 단계의 브라우저 기록을 이번 변경의 검증으로 취급하지 않습니다.

2. 드래그 시작/해제 위치, 답변 드롭 판정, 터치·탭, 관성·충돌·유리 파편·꼬리의 시각 연결.
3. 반복 선택·삭제·질문 왕복·건너뛰기·Q10 직접 입력의 실제 UI 조작.
4. 질문 진행·역방향 이동에서 하늘 좌표의 연속성, 움직임 감소·부유 멈추기.
5. 선택·삭제·건너뛰기 시 RAF 루프가 불필요하게 재생성되지 않는지 런타임 측정.

## 남은 한계

- 상태는 React 메모리에만 보관하므로 새로고침 후 복원되지 않습니다.
- 직접 입력한 키워드는 원문과 답변 맥락을 보존하지만 의미 가중치는 미분류입니다. UI 프로필 분류를 의미 분류로 간주하지 않습니다.
- 의미 계열·질문 맥락은 아직 새 API에 연결하지 않았습니다. 기존 분석 모델이 맥락을 정확하게 해석하는지는 이번 단계에서 보장하거나 실제 호출로 검증하지 않았습니다.
- Q10 개인화 추천·함축·사용자 승인, 최종 의미 집계, 캡슐 해체·새 3D 오로라는 미구현입니다.
- 많은 사용자 캡슐에서 기존 O(n²) 충돌 비용과 긴 문장 배치 부담이 남습니다. 실제 기기 FPS와 Safari는 미검증입니다.
