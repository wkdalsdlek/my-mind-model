# Preview 해석 입력 상한 확장 — 120KB Beta 검증

## 확인된 원인과 아직 모르는 부분

이전 Preview 장애는 `interpretation / INPUT_BYTES_EXCEEDED`, 측정값 47,336바이트,
기존 Secret 상한 16,000으로 확인됐다. 이후 독립 설정 60,000과 타임아웃 개선이 배포됐다.
현재 사용자가 보고한 새 `MODEL_BUDGET_MISMATCH`의 구체적 유형은 아직 확인되지 않았다.

`ModelPermit.run`에서 이 오류를 만드는 조건은 다음 세 가지다. 동시에 발생하면 모두 기록한다.

| mismatchTypes | 차단 조건 |
| --- | --- |
| MODEL_NAME_MISMATCH | 요청 모델이 `featureModel(feature).model`과 다름 |
| MAX_OUTPUT_TOKENS_MISMATCH | `max_completion_tokens`가 정책과 다름. 누락/null 포함 |
| INPUT_BYTES_EXCEEDED | `Buffer.byteLength(JSON.stringify(params), "utf8") + 4096`이 유효 상한을 초과 |

현재 해석 라우트와 정책은 모두 `gpt-6.1-sol`, 최대 출력 25,000으로 일치한다.
추론 `medium`, strict 응답 스키마, 프롬프트, 철학적 해석, 오로라 렌더링은 변경하지 않았다.
따라서 확인하지 않은 모델/출력 문제를 추측해 값을 바꾸거나 검증을 해제하지 않았다.

Vercel CLI를 통한 지정 Beta Preview 배포의 기본 최근 30분 로그 조회는 성공했으나
일치 로그가 0개였다. 명시적 `--since` 조회는 CLI 옵션 오류로 실행되지 않았다.
현재 장애가 없었다거나 입력 초과였다고 단정하지 않는다. 재발 시 기존 Preview 전용
`[private-beta-model-budget]` 로그의 `mismatchTypes`, `inputBytesWithOverhead`,
`maxInputTokens`와 출력 한도 숫자로 원인을 구분해야 한다.
원본 로그, 답변, 승인 문장, 프롬프트, 계정 식별정보, 토큰·키·DB URL은 기록하지 않았다.

## 최소 구현과 적용 범위

제품 소스 변경은 `policy.ts`의 명시적 설정 최대값 **60,000 → 120,000** 한 곳이다.
다른 보안·사용량·모델 호출 코드는 기존 구현을 그대로 사용한다.

| 상황 | 동작 |
| --- | --- |
| Preview + interpretation + 미설정 | 기존 Secret의 입력 상한 그대로 사용 |
| 명시적 `AI_INTERPRETATION_MAX_INPUT_BYTES=60000` | 기존 60,000 유지. 자동으로 증가하지 않음 |
| 명시적 `...=120000` | 해석 요청의 유효 입력 상한 120,000 |
| 잘못된 설정 | DB 예약/SDK 호출 전 503 `BUDGET_NOT_CONFIGURED` |
| Q10 closing / legacy analyze | 새 설정을 읽지 않고 기존 정책 유지 |
| Production / development 등 Preview 외 | 새 설정 무시, 기존 정책 유지 |

허용 범위는 4,096~120,000의 정규 정수 문자열이다. 공백·부호·지수·소수·선행 0·
빈 문자열·120,001 이상은 거절한다. 기존 필수 가격/예산 설정도 계속 검증한다.

2026-10-18 KST 읽기 전용 조회에서 실제 Preview의 입력 설정은 **60,000**으로 확인했다.
이 작업에서는 환경변수를 바꾸지 않았으므로 90/110KB를 Preview에서 허용하려면 별도 승인 후
코드 배포와 Preview 전용 설정 `120000` 적용이 필요하다. 기존 Secret 가격표는 그대로 둔다.

## 호출 전 검사·예약·정산의 일관성

`featureBudgetConfig`는 기본 설정을 검증한 뒤 해석 요청 전용 복사본의 입력 상한만 바꾼다.
공유 Secret이나 단가는 변경하지 않는다. `reserveUsage`가 확정한 동일 복사본을 다음에 사용한다.

1. 입력 유효 상한 + 출력 25,000 + 최대 2회로 호출 **전** 최대 비용 예약.
2. 사용자/전역 일간·월간 예산, 이전 청구액과 진행 중 예약액 검사.
3. `price_snapshot.maxInputTokens`에 동일한 상한 저장.
4. `ModelPermit.run`에서 전체 SDK 파라미터의 UTF-8 바이트 + 4,096 검사.
5. 공급자 `prompt_tokens`도 같은 상한으로 검증하고, 출력·캐시·추론 토큰 검증 유지.

요청 시작 뒤 설정이 바뀌어도 이미 예약한 permit의 상한·예약액은 바뀌지 않는다.
바이트 수를 실제 토큰 수로 단정하지 않는다. 기존 보수적 토큰 상한 추정 방식을 유지한다.

한도는 본문 답변만이 아니라 프롬프트·메시지·인용문 카탈로그·리본 근거·응답 Schema와
오버헤드를 포함한다. 이 문서의 KB는 1,000바이트 기준이다.
120,000과 정확히 같으면 허용하고 120,001부터 거절한다. 재시도 추가 메시지도 매번 포함한다.
첫 시도 사용량이 확인된 뒤 두 번째 요청이 초과하면 첫 비용을 정산하고 추가 SDK 호출은 막는다.
취소·통신 실패·알 수 없는 사용량은 기존처럼 예약액을 유지한다. 최대 2회와 70/85/95초 기한도 유지한다.

## 비용 영향

입력 단가 I, 출력 단가 O (USD / 100만 토큰)일 때:

`R = ceil(2 × (상한 × I + 25,000 × O) / 1,000,000 × 10^8) / 10^8`

| 유효 상한 | 기존 참고 단가 I=2, O=10일 때 최대 예약 |
| --- | --- |
| 16,000 | $0.564 |
| 60,000 | $0.74 |
| 120,000 | **$0.98** |

캐시 할인은 예약에 미리 적용하지 않고, 추론 토큰은 출력 25,000 안에 포함한다.
실제 Secret 단가는 조회·수정하지 않았다. 위 금액은 공식 최신 가격이 아니라 기존 참고 단가의 계산이다.
실제 예약은 기존 Secret 단가로 계산되며 입력 확장만으로 비용 검증을 우회하지 않는다.

입력 증가로 한 번의 예약이 예시상 $0.24 커진다. 사용자·전역 일간·전역 월간 잔액이
각각 예약액 이상이어야 하며 부족하면 기존 HTTP 429 `AI_BUDGET_LIMIT`로 차단한다.
`MODEL_BUDGET_MISMATCH`(503)와 횟수·금액 제한(429)은 서로 다른 검사다.

## Beta 계정 한도 점검과 승인 후 필요한 변경

### 실제 읽기 전용 확인

기존 Neon `my-mind-model` 프로젝트의 **beta-staging / neondb**를 READ ONLY 트랜잭션으로 조회했다.
계정 이름·이메일·ID·세션을 조회하지 않고 역할/상태별 설정과 개수만 집계했다.

| 항목 | 확인값 |
| --- | --- |
| 활성 Owner 계정 | 1개 |
| Q10 일간 | 20회 |
| 해석 일간 | **10회** |
| 레거시 분석 일간 | 10회 |
| 계정 monthlyBudget | NULL — 공통 `AI_USER_MONTH_USD` 사용 |

Vercel의 사용자/전역 예산 및 횟수 설정 값은 Secret이라 읽을 수 없었다.
따라서 현재 월 예산을 테스트 fixture의 $5 등으로 단정하지 않는다.
Preview의 DATABASE_URL도 가져오지 않았으므로 이 DB와 실제 Preview 연결값을 직접 대조한 것은 아니다.
변경 시에는 운영자가 Preview DB 대상과 계정을 다시 확인해야 한다.
Production/main DB 및 모든 계정 데이터는 변경하지 않았다.

### 이미 지원하는 정책과 권장 변경안

- 기존 관리 CLI `limits`는 해석 일간 10과 계정별 월 예산 $20~30을 이미 지원한다.
  신규 Tester 기본 해석 일간은 3, Owner 기본은 10이다. 자동 기본값이나 기존 계정을 수정하지 않았다.
- 현재 확인한 Owner의 해석 일간은 이미 10이므로 같은 값을 다시 바꿀 필요가 없다.
  월 $25를 예시 목표로 정하면 승인 후 **해당 계정의 monthlyBudget=25**만 적용하는 방법이 있다.
  새 Tester를 만들거나 기존 계정을 조정할 경우 interpretationDaily=10을 명시하고,
  기존 Q10/레거시 일간 설정은 보존한다. 계정 생성/한도 변경은 이번에 실행하지 않았다.
- 계정별 월 예산은 Q10·해석·레거시 분석을 합친 사용자 예산이다.
  공통 사용자 예산 Secret을 덮어쓰지 않고 계정 override를 사용할 수 있지만 전역 한도는 계속 적용된다.
- 전역 일간·월간 금액/횟수 및 동시성의 실제 설정을 운영자가 확인해야 한다.
  예시 단가에서 사용자 1명이 하루 10회 모두 최대/불확실 비용을 쓰면 $9.80이며,
  다른 기능과 사용자가 있다면 전역 일간 예산에 그만큼 여유가 추가로 필요하다.
  N명에게 월 $25를 보장하려면 전역 월간 한도도 최소 그 합과 기타 사용량을 감당해야 한다.
- 월 $20/$25/$30은 모든 시도가 $0.98로 유지되는 경우 각각 약 20/25/30회분이다.
  하루 10회는 일간 상한이며 월 예산 안에서만 가능하다. 하루 10회 × 30일의 최악 비용은
  $294 + 기타 기능 비용이므로 월 $20~30으로 매일 최대 사용을 보장할 수는 없다.
  확인된 실제 사용량은 더 낮게 정산할 수 있지만 실측 없이 평균 비용을 약속하지 않는다.

관리 절차는 기존 `npm run beta:admin -- limits`의 대화형 입력을 사용한다.
DB 대상·계정·현재 Q10/레거시 값을 확인하고, 승인된 경우에만 해석/월 예산 값을 변경한다.
비밀번호나 이메일을 코드·로그·명령 인수에 기록하지 않는다.

## 변경·보존 범위와 남은 확인

변경 파일은 다음 4개다.

1. `lib/server/security/policy.ts` — 명시적 Preview 해석 입력 설정 최대값만 120,000으로 확장.
2. `tests/interpretation-input-budget.test.mjs` — 입력/원인 구분/예약·정산/Beta 계정 정책 회귀.
3. `tests/private-beta.test.mts` — 독립 DB 전용 확장 한도/동시 예약/계정 한도 검증.
4. `docs/interpretation-input-budget-verification.md` — 실제 확인값·미확인값·변경안·결과.

기존 미커밋 인증 진단 작업, 환경 파일, ZIP, Git HEAD와 모든 브랜치를 보존했다.
커밋·푸시·배포·환경변수 수정·운영 DB 쓰기·계정 설정 변경·유료 AI 호출은 수행하지 않았다.

다음 승인 전까지 새 설정과 계정 변경을 적용하지 않는다. 최신 장애 로그의 정확한
불일치 유형, 실제 Secret 예산/단가와 잔액, Preview DB 연결 대상, 모델 실제 컨텍스트 한도·
응답 품질·지연은 아직 추가 확인이 필요하다. 120KB가 모든 답변 조합을 포괄한다고 보장하지 않는다.
