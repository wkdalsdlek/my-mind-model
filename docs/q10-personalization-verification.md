## 추천과 데이터

- `q10-recommendations.ts`는 Q1~Q9의 실제 `SelectedCapsule[][]`와 응답 상태를 사용합니다. `serializeSelections`를 개인화 입력으로 사용하지 않습니다. Q10 자신이나 아직 선택하지 않은 추천은 근거에서 제외합니다.
- 로컬 방식이며 AI 요청·새 API·API 키·추가 의존성이 없습니다. 같은 구조화 입력에 같은 결과를 반환합니다. 질문·고정 키워드 순서, 정렬된 선택 ID, 의미 계열 라운드 로빈으로 순서를 고정합니다. 같은 계열 안에서는 덜 반영된 질문의 근거를 우선하여 Q1에만 추천이 편중되지 않게 합니다.
- 추천은 `PersonalizedKeyword`이며 안정적인 ID, 라벨, 기존 UI 그룹, 일곱 의미 계열 가중치, `source: personalized`, 추천 종류·생성 경로·근거·입력 스냅샷을 기록합니다. 근거에는 질문 ID, 키워드 ID, 개별 선택 ID, 원문과 질문의 `answerIntent`가 있습니다.
- 같은 단어의 반복 선택은 근거 ID를 모두 보존하되 근거의 다양성으로 중복 계산하지 않습니다. 정규화한 라벨과 주제 키로 중복을 제거하고, 주 의미 계열당 최종 후보를 최대 3개로 제한합니다.
- 결과 검증에서도 주제 키의 유일성과 의미 계열별 상한을 검사합니다. 서로 다른 라벨·ID를 사용하더라도 같은 주제이거나 한 계열에 편중된 잘못된 출력은 허용하지 않습니다.
- 6개 이상 서로 다른 표현과 3개 이상 질문에 응답했다면 직접 6개·확장 5개·공통 3개를 목표로 합니다. 3개 이상 표현과 2개 이상 질문은 직접 최대 4개·확장 최대 3개, 그보다 적으면 직접 최대 2개·확장 최대 1개입니다. 실제 후보·다양성이 부족하면 공통 표현으로 채워 정확히 14개를 반환합니다.
- 자유 입력이 같은 질문의 고정 표현과 정확히 일치하면 해당 질문의 의미 매핑을 사용합니다. 그 외 의미를 알 수 없는 원문은 직접 재제안하고 `semanticStatus: unclassified`, 빈 가중치로 명시합니다. 분류를 임의로 만들거나 의미 확장 근거로 사용하지 않습니다.
- 공통 표현은 근거 배열이 비어 있으며 사용자의 가치라고 주장하지 않습니다. 추천 생성·결과 검증 실패에는 결정적인 공통 표현 14개를 반환하고 UI에서도 대체 사실을 표시합니다.
